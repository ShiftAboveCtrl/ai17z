**The half of the last fix that would have noticed first.**

Beta 4.5 made an X read record a session X has stopped accepting, so an installation whose sign-in had lapsed stopped reporting itself as connected and healthy. That covered a read somebody asks for. It did not cover the one that matters more.

The radar polls on its own schedule, all day, against every source an owner has added. A lapsed session shows up there long before anybody opens a screen or an agent reaches for a capability. That path had its own handling for the outcome, and all it did was write a sentence onto the source's row, so the account went on reading connected while every monitor quietly returned nothing.

Both read paths now record it, under the same rule: only for an account that was connected, because one that never had a session is a different thing and must not be overwritten with a state meaning it used to work; and never for a rate limit, because sending somebody to re-authenticate a working account over a slow-down is worse than saying nothing.

It is recorded at the two places that hold the channel context rather than inside the function that decides what to do with an answer. That one is deliberately given only what it reads, so it can be tested without a browser, and widening it to reach an account would have cost exactly the property that makes it testable.
