**Two things that stopped AI17Z installing on a Mac.** Both were found by somebody installing it on a real Mac, and neither could have been found any other way — the machines that build and test these packages cannot have Docker Desktop, which is exactly where both faults lived.

**If you tried Beta 1.0.0 (17) or (18) on a Mac and it did not work, this is the release to try.** The commands are unchanged.

---

## Docker never reached your Applications folder

AI17Z downloaded Docker's disk image, mounted it, and then opened `Docker.app` **out of the mounted image** while telling you to "follow Docker Desktop's installer". A `.dmg` is a disk image, not an installer — there was no installer to follow. It ran Docker from a read-only volume, then ejected that volume, so Docker never reached `/Applications` and its engine never came up. What you saw was Docker failing. What actually happened was AI17Z handing you over wrongly.

What happens now, if Docker Desktop is missing:

1. AI17Z offers to run **Docker's own command-line installer**, which lives inside the image and which Docker documents. It puts Docker Desktop in `/Applications`. It needs your administrator password, and `sudo` asks for it — AI17Z never sees it.
2. If you would rather do it yourself, or that does not finish, **the disk image opens in Finder** and AI17Z tells you to drag `Docker.app` onto the Applications folder beside it.
3. Either way it then **watches for the application to appear** rather than asking you to press a key when you are done. A keypress proves somebody pressed a key; this proves Docker is actually there.
4. Then it starts Docker and waits for the engine to genuinely answer.

**AI17Z still never accepts Docker's licence for you.** Docker asks you the first time it runs. The flag that would answer it on your behalf appears nowhere in AI17Z and never will.

## Setting up failed with a missing `node-gyp`

If you got past Docker, the first launch failed like this:

```
npm error Cannot find module 'node-gyp/bin/node-gyp.js'
  npm install failed.
  Setting up failed.
```

Two mistakes meeting.

**A packaged copy was running `npm install`.** It ships its dependencies — nearly five thousand files of them — and the first-launch setup was the script a *developer* runs in a clone, which installs them. A package reaching the network to reconcile its own dependencies against `package.json` on your machine is a different program from this one. It now recognises that it is a package and skips that step entirely.

**And the bundled Node runtime had `node-gyp` pruned out of it** to save space. That does not merely remove the ability to compile native add-ons: npm looks for `node-gyp/bin/node-gyp.js` before it runs *any* script at all, whether or not anything is being compiled. So the bundled npm could not run a script — which is what produced that error. It is back.

## Why the tests did not catch either

Worth saying plainly, because it is the same reason twice.

The hosted Macs that build and exercise these packages have no Docker Desktop and cannot be given one — its installer is a disk image with a graphical setup and Docker's own licence, which AI17Z must never accept for anybody. So those runs answer the `docker` command at the vendor boundary, precisely so everything *after* the Docker gate can be tested. That stub made the Docker handover unreachable.

And every one of those checks ran `tsx`, which is what the browser worker needs, while none ran `npm`, which is what first-run setup needs.

Both gaps are now closed as far as a machine can close them: the packaging runs ask the bundled npm to actually run a script, and the Docker handover has tests over its shape. Neither can prove the Docker path works on a real Mac — `docs/MACOS_TEST_CHECKLIST.md` says which steps still need a person, and that list is honest rather than aspirational.

## Everything else

Unchanged from Beta 1.0.0 (18): Windows, macOS on Apple Silicon and Intel, Ubuntu 22.04 / 24.04 / 26.04 on amd64 and arm64, each package built on a machine that really is that architecture. Installation commands, paths, data locations and security posture are all the same.
