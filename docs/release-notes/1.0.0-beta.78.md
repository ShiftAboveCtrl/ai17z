`v1.0.0-beta.78` lets an agent's own Solana wallet swap one token for another,
with you approving the exact transaction first, and lets anybody ask what a
swap would get right now.

## What a swap would get

**`market.swap_quote`** asks Jupiter's current Swap API for two exact Solana
mints and an exact amount: what the swap would deliver now, the least the
route promises, the price impact, the fee and the venues it goes through. It
names no wallet, so the answer carries no transaction and nothing can be
signed from it. It is asked again every time, never served from a cache, and
it is on the shared runtime, so AI17Z Studio can price paper trades and
proposals from a real quote.

A Solana token's record now carries its picture, as a web address.

## Swapping from an agent's wallet

A third kind of wallet transaction, beside sending the native coin and
sending a token. You choose the two tokens, how much to spend and the least
you will accept. Then:

- The wallet adapter builds the swap through Jupiter's own router and
  simulates it.
- Before you are asked, AI17Z refuses it if anybody else pays its fee, if it
  needs a second signature, if it calls any program a Jupiter swap does not,
  if the route promises or the simulation delivers less than your minimum, or
  if more SOL would leave the wallet than the swap, its fee and account rent
  explain.
- You approve the digest of that exact transaction. A swap is valid for a
  minute, because Solana refuses older ones; after that it is simulated again.
- After signing and before sending, AI17Z reads the signed transaction back
  and sends nothing unless it is the one you approved.

Nothing swaps on its own. Every swap is one you approved.

## Upgrading

One migration, `0109_wallet_swap_intents`, which widens what a wallet
transaction may be. Swapping needs a wallet adapter that knows how; one that
does not says so when you simulate.
