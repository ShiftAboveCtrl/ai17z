**Your agent can reach its own tools, had never noticed anything on its own, and stops telling everybody the same thing.** Beta 4.1 fixed what an agent recorded. This one is about what it can actually do with what it knows, and it started with a command that could not answer.

## /help works

Asking the bot what you could type produced nothing at all, while `/health` answered normally. Four of the eleven commands take an argument, and the placeholder went into the message unescaped, so Telegram received a literal `<id>`, read it as markup it did not recognise, and refused the whole message. The refusal was logged where nobody reads it, and the sweep does not retry a command it has already acknowledged, so you got silence.

Verified against Telegram before and after: the old message is rejected with "Unsupported start tag", the fixed one arrives.

Two things changed beyond the escaping. A message Telegram cannot parse is now sent again as plain text, so a formatting mistake costs the formatting rather than the whole message. And the bot offers its command list to Telegram itself, scoped to your chat only, so the app can complete them as you type. `/help` answers regardless of whether that worked.

## Your agent can use its tools

AI17Z has seventy-three things an agent can look up: the time, its own health, what it remembers, what a repository shipped, a token price, whether a contract is verified. An agent with the model-callable loop switched on could reach none of them in practice.

The reason was volume. Every one of them was described to the model on every reply, which is twenty thousand characters of menu wrapped around a three thousand character question. Asked the time, the agent ran a web search instead and answered "I don't know" while the clock sat in the list it had been handed.

**The agent is now shown only the few capabilities that bear on what it was asked.** Asking about the time offers it the clock. Asking what a project shipped offers it the repository. Banter offers it nothing at all, which is both correct and the cheapest thing it can do. The narrowing is deterministic, so you can see why something was offered, and it reads only what each capability already says about itself.

Proven end to end against a real model: asked the time in Tokyo it read the clock and answered 17:33 JST; asked whether its browser was working it read its own diagnostics and named the four live tabs; asked what it remembered about somebody it searched and said plainly that it remembered nothing rather than inventing them; asked what a repository shipped it was refused for a missing argument, read the reason, corrected itself and answered with the real release.

**Nothing was switched on that was off.** The two capabilities that write anything remain disabled by default.

## It stops repeating itself

An account was posting the same observation about one feature three times in sixteen hours.

Underneath, the agent held positions at high confidence on **"Better", "Good", "Keep", "Best", "Open"** and **"Permanent"**. Eight of its twelve recorded positions were the first word of a sentence in one of its own replies. The rule against that existed and only ever checked the first sentence, so every later sentence donated its opening word. Those became things worth saying, and then things worth posting.

A word is now judged wherever its sentence starts. A name is still a name in that position, so GitHub and AI17Z survive being the first word while "Better" does not. And a subject the account has covered in its last dozen posts is not raised again: repeating yourself to different people in replies is answering, doing it in posts is being boring in public.

## Your agent had not noticed anything for a fortnight

The part of AI17Z that thinks between the things it is asked has been running on
schedule, on time, and looking at nothing at all.

It reads what has arrived since the agent last looked. The worker claims an
agent that is due in one database statement, and that statement was also
recording the time as the moment the agent last looked. So the wake it had just
started was handed a window beginning at its own first instant, and there was
never anything inside it.

On this installation: nineteen consecutive runs recording "looked at 0 things",
a hundred and forty-two posts sitting in the window each of them should have
covered, three hundred and ten keyword matches collected over two days, and not
one of them ever seen. The working set held twenty-three items, every one of
them produced by somebody pressing "think now", which takes a different route
and worked perfectly. That is why nothing looked broken.

**Everything downstream of it was dead and reported as quiet.** Interests,
questions, hypotheses and concerns are all things the agent forms from what it
noticed, so it formed none. Curiosity had nothing to look into. Nothing was
learned from how a reply went. The only route an agent had to a post of its own
was the one that starts from a position it took in a reply, which is exactly the
route that produces an account talking about the same feature three times.

The run that fails now leaves the window open rather than closing it. A wake
that was paused, or one that threw, records why and backs off, and the next one
still sees what arrived while it was failing. An observation skipped is skipped
for good, because the window only ever moves forward.

## How fast a reply should be, as a real setting

Three settings under Automation: Fast, Balanced, Thorough. Balanced is what
every agent already did, so nothing changes until you move it.

They are not labels. Measured on this installation, per reply: writing the
answer takes 10.2 seconds at the median, rewriting it in the agent's own voice
takes 24.9, and deciding what to look up takes 10.6 against a bound of three and
a half. So the voice rewrite is the largest optional cost there is, and the
research plan is the one most often paid for and thrown away.

**Fast** answers with one model call. It still reads the thread, remembers,
looks things up, and is checked before anything is sent. What it gives up is
the model rewrite and the model's opinion about what to look up.

**Thorough** waits twenty seconds for that opinion instead of three and a half.
The measured spread puts three quarters of those answers under 15.6 seconds, so
Balanced keeps about a quarter of them and Thorough keeps most.

No setting makes a reply skip a check. A faster reply that is validated less is
not a speed setting, it is a different promise.

## You can ask any reply why it said that

The account of how an answer was reached was written for the Response Lab, so the only replies you could inspect were the ones that were never sent. It is built entirely from what an ordinary reply already records.

**It now sits on every job.** What it said, what it could see with anything missing named rather than left blank, and each stage with what it decided. The full trace is still underneath. No hidden reasoning is stored or shown, here or anywhere.

The lookups stage shows what the agent was offered as well as what it used. "It did not look that up" has two causes that look identical from outside: it was never shown the thing that could answer, or it was shown it and answered anyway. Those need opposite fixes.

## Memory pressure stops lying

The health screen said AI17Z had paused background work when memory got tight. Nothing was paused. Of the three things the pressure system decided, one was read and two were not, so the only real effect was running fewer jobs at once.

It also changed its mind constantly, because it re-measured on every tick and free memory moves every second.

Now: a worse reading has to hold for twenty seconds before it is believed and a better one for two minutes, so a machine sitting near the line stops flapping. And what gets given up is ordered and enforced. **Mentions, replies, your Telegram commands and recovery never stop, at any pressure.** Watching repositories and feeds goes first. Thinking and engagement stop only when memory is genuinely critical. The health screen says which of those is happening.

## You are told when it cannot see X

This machine lost power while the release was being prepared, which turned out
to be the most useful test of the week.

Everything in Docker came back by itself. The piece that drives your browser is
not in Docker, because a container cannot reach a browser on your own machine,
and nothing started it again. So the installation came back looking healthy in
every respect except the one that matters: the database was up, the account
still read connected, and it could not read or answer a single mention.

The health screen said so. Nobody was looking at the health screen at six in
the morning.

**AI17Z now tells you**, through the same notifications that already reach your
phone. It waits ten minutes first, because a normal restart spends a few of
them rebuilding before a browser exists, and it stays quiet when the real
problem is simply that nothing is running yet.

Nothing was added to your machine's startup to achieve this. AI17Z still
installs no Run key, no scheduled task and no service.

## Smaller things

**Replies are quicker.** The step that asks a small model what to look up was given six seconds and typically takes eleven, so it failed more often than it worked and charged almost every reply the full six seconds to find out. It gets three and a half now, which is where it actually lands when it lands at all.

**There is a way to ask where the time goes.** `npm run latency` reports each stage from what already happened. On a live installation: somebody posts, AI17Z sees it in half a minute, and the reply is live in under three. Its first version asked the database for a word the column cannot hold, so it reported every model call ever made as one that had failed. That is fixed, and a test now reads the query rather than trusting it.

**Three addresses nothing ever called** have been removed.

**An agent brings what it is working on into a conversation.** Goals reached the part that decides what to notice and went no further, so an agent could be asked what it was working on and had nothing to answer from.

**The rehearsal corpus is eighty-three situations**, up from fifty-one. The new ones are the shapes that were missing rather than more of the same: instructions hidden inside a mention, being asked what to buy, being asked to predict a price, being asked to pretend to be a person, being one of thirty accounts tagged, a pronoun with two possible antecedents, a thread revived after a month, and being asked what it is unsure about.
