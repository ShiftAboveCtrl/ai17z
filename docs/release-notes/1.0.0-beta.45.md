**Plugins.** What an agent can reach for is now something you install, configure and trust by name, on a screen of its own, and an agent can be extended with something nobody wrote into AI17Z.

## What a Plugin is

A Plugin is the unit you install and decide about. The six groups of capabilities that already shipped are now the built-in Plugins, presented rather than copied, so nothing about what your agents can already do has changed.

What is new is that a Plugin can also arrive from somewhere else. One that does declares a bounded operation rather than shipping code: one request method, an allowlist of hosts it may reach, a typed question, a typed answer, a timeout and a ceiling on how often it may run. AI17Z builds the request from that declaration. There is no downloaded JavaScript, no install script, no shell, and no way for a Plugin to reach your files, your signed-in browser, your provider keys, another agent's memories, or a host it did not name.

## Deciding about one

Plugins is a top-level screen, and it is the place these decisions are made. Choose an agent, and each Plugin shows what it contains, what each capability is permitted to do, whether it can actually run right now and why not when it cannot, what it has reached for recently, and what you still owe it before it will work.

Each capability still has its own switch. Turning a Plugin on sets each of its capabilities to its own default, which means reading is allowed and anything that changes something still asks you or stays off. Turning a Plugin on has never been consent to let it act, and it still is not.

An agent's own page shows the same facts and sends you here to change them. Two screens that both looked authoritative about one setting is how something ends up allowed on one and refused on the other.

## Configuration and credentials

A Plugin that needs a key or a setting asks for it per agent, because two agents on one machine are two different accounts as far as an API is concerned. A credential is sealed on your machine the same way a provider key is. It is never shown again, never returned by anything, never written to a log or an audit row, and never carried in an exported agent.

## Installing, updating, removing

A Plugin file is checked before anything is registered: the shape, the version this build can run, the hosts, the credential slot, and the checksum published beside it. Anything that does not add up is refused with a sentence rather than half-installed.

A new version that asks for more than the one you approved stops and says exactly what it now wants, in sentences, and waits for you. A version arriving under a different publisher is a substitution and is refused. So is a version older than the one installed, unless you ask for it.

Removing a Plugin takes its capabilities, its configuration and its sealed credentials with it. Reinstalling it later does not quietly restore a permission you last thought about a year ago. What your agent did with it stays in the history, because removing a tool does not undo having used it.

## Two things a Plugin may unlock

A Plugin can offer itself as somewhere the research step looks, under its own name, so an answer says where it came from rather than arriving as something the agent knew. It runs through the same permission, readiness, ceiling and audit trail as everything else, which means a Plugin you switched off is a source you switched off.

A Plugin can also have a panel of its own on the Plugins screen. It is drawn from a title, sentences and links to hosts it already declared. A Plugin never hands back anything to render.

## The registry

AI17Z can read a catalogue of Plugins over the network. There is no address built in and no public registry deployed yet, so until you set one, the screen says so and installing from a file works exactly as well. An address has to be https, and one that is not is now refused when you save it, with a reason, instead of being quietly discarded.

## New agents

A brand new agent now starts with a small, deliberate set switched on: looking terms up in reference sources, reading a page or a feed it is pointed at, checking the clock, and searching its own memory. Everything else starts off, including anything that writes.

Nothing about an agent you already have changes. Existing agents keep every decision they had, and that is checked rather than intended.

## Moving an agent between machines

An exported agent now names the Plugins it was using, with the publisher and version, and carries the settings you gave them. It does not carry the Plugin itself, and it never carries a credential. So opening somebody's agent file installs nothing, and an import tells you which Plugins to add and which keys to enter rather than leaving you to discover it when something quietly fails.
