AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on. Everything runs where you are: your data, your credentials, your browser session.

**This is the first release you can install on a Mac or on Ubuntu.**

Until now AI17Z was a Windows program. It now has first-class packages for macOS — Apple Silicon and Intel — and for Ubuntu on both amd64 and arm64, each built on a machine that really is that architecture and each run there before this release existed.

---

## Windows

Open **Windows Terminal** and paste this:

```powershell
irm https://raw.githubusercontent.com/ShiftAboveCtrl/ai17z/main/install.ps1 | iex
```

Nothing is downloaded by hand, nothing is double-clicked, and no Windows security setting is touched. Unchanged from the last release, and still the only supported way in.

## macOS

Requires **macOS 13 or newer**, on Apple Silicon or Intel.

```bash
curl -fsSLO https://raw.githubusercontent.com/ShiftAboveCtrl/ai17z/main/install-ai17z-macos.sh
less install-ai17z-macos.sh
bash install-ai17z-macos.sh
```

The middle line is not decoration. Read it before you run it — that is why it is a file you fetch rather than a command you pipe into a shell.

It works out whether this Mac is Apple Silicon or Intel, downloads the package built for it, **checks its SHA-256 against the hash this release published**, and unpacks it into your own Library. Everything lives in `~/Library/Application Support/AI17Z/`, so **AI17Z itself never asks for `sudo`** — including when it updates.

**These packages are not signed with an Apple Developer ID and are not notarized.** AI17Z has no Apple Developer account. The installer says so on screen before it unpacks anything, and **nothing here disables Gatekeeper, strips a quarantine attribute, or argues with either**. [What that actually means](https://github.com/ShiftAboveCtrl/ai17z/blob/main/docs/MACOS_TRUST.md) is written out in full, including which prompts are Docker's or Google's rather than AI17Z's.

**Node is inside the package.** A pinned Node runtime is fetched from nodejs.org at build time, verified against its published checksums, and shipped with AI17Z. Nothing consults your PATH and nothing installs a system Node. **Git is not required.**

**Docker Desktop is required** — AI17Z uses it for the database. If it is missing, the installer offers Docker's own installer and Docker collects its own licence acceptance; AI17Z never accepts a vendor agreement for you.

**Google Chrome is required only for browser-backed channels** such as X. The browser worker runs natively on the Mac, drives real Chrome with a profile of its own, and never touches your everyday browser.

More: [Installing on macOS](https://github.com/ShiftAboveCtrl/ai17z/blob/main/docs/MACOS_INSTALL.md)

## Ubuntu

**22.04, 24.04 and 26.04 LTS**, on amd64 and arm64. All three are installed and exercised on every change.

```bash
curl -fsSLO https://raw.githubusercontent.com/ShiftAboveCtrl/ai17z/main/install-ai17z-ubuntu.sh
less install-ai17z-ubuntu.sh
bash install-ai17z-ubuntu.sh
```

Run it as yourself. It asks for `sudo` exactly where installing a system package needs it and **refuses to run as root** — your agents, keys and browser session belong to you, and a root install leaves files in your home you cannot then delete.

It picks the `.deb` for your architecture, checks its SHA-256, and installs it with apt. **Node is inside the package**, same as on macOS; **Git is not required.**

**Docker Engine** comes from Docker's own APT repository, by Docker's documented method. Adding yourself to the `docker` group is equivalent to root on that machine, and the installer says so before offering it.

**Ubuntu Server is a supported arrangement, not a degraded one.** Everything runs except browser-backed channels, which need a graphical session and Chrome. `ai17z doctor` reports that as *not available* rather than as a failure, and nothing installs a desktop to pretend otherwise.

**Installed services are reachable from your machine and nowhere else.** The interface, the API and the database are published on `127.0.0.1`. To reach a server from elsewhere, forward a port over SSH rather than opening one:

```bash
ssh -L 8080:127.0.0.1:8080 you@your-server
```

If you deliberately change that, `ai17z doctor` tells you every time it runs.

More: [Installing on Ubuntu](https://github.com/ShiftAboveCtrl/ai17z/blob/main/docs/UBUNTU_INSTALL.md) · [What it touches](https://github.com/ShiftAboveCtrl/ai17z/blob/main/docs/UBUNTU_SECURITY.md)

## Updating

Every platform updates itself, and every update asks one question first: **can this machine run the version that is arriving?**

That check happens **before anything stops**. Wrong Docker, an unsupported OS, a missing build for your architecture — each refuses and changes nothing, leaving the AI17Z you have installed and running. A missing Chrome is deliberately *not* a refusal: a headless server has none and must still take updates.

The decision lives in one place and all three platforms ask it. An installation made before that check existed keeps its old behaviour; a current one whose check cannot run **refuses to update** rather than pressing on and finding out afterwards.

Your data is never part of an update. The program directory is replaced; `.env`, your master key, your database and your signed-in browser profile are not.

## Security and integrity

- Every package's SHA-256 is published in `SHA256SUMS.txt`, and every installer checks it **before** unpacking or installing. There is no flag to skip it.
- `release-manifest.json` is the machine-readable description of this release — every asset, its hash, its platform and architecture, and what a machine needs to run it.
- Artifacts carry **GitHub build provenance**, which is an attestation that these bytes came from this repository's workflow at this commit. It is **not** code signing, **not** Apple notarization and **not** Canonical signing, and is not described as any of those.
- Each package is built on a runner that really is that architecture, and the build refuses to continue if it is not.
- Every published package is unpacked and scanned before release for anything belonging to whoever built it or to an owner.

A checksum published by the release it describes catches a corrupted or truncated download. It is not a defence against a compromised release, and [the audit document](https://github.com/ShiftAboveCtrl/ai17z/blob/main/docs/SETUP_AUDIT.md) says exactly that rather than implying otherwise.

## Known interactive checks still outstanding

Machine-run proof cannot represent a person sitting at a computer. These are honest gaps, not oversights:

- **macOS:** Gatekeeper's dialog for a genuinely downloaded file, quarantine behaviour, Terminal's paste protection, and Docker Desktop's graphical first run and licence.
- **Both platforms:** signing in to X through a real Chrome window, and the browser worker on a machine with an actual screen.
- **Ubuntu Desktop:** Wayland/X11 session integration and the desktop launcher.
- **Either:** behaviour across a physical reboot.

If you hit any of these, please say what actually happened — including nothing happening.
