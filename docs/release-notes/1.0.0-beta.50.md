**The Social Radar could stop completely and go on reporting that every monitor was healthy.** It did, on two installations at once, for an hour and a half. This is the fix, and it is the reason the improvements in Beta 5.9 were not doing as much as they looked.

## What happened

One poll that never came back ended all discovery.

The radar guards itself so two polls cannot overlap: while one is running, the next tick returns immediately. That guard has no deadline. A poll that never finishes therefore does not slow the radar down, it stops it for good, and every tick after that returns at the first line without claiming anything.

Nothing failed, so nothing was marked as failed. Every source kept the status it last had, which was healthy. The browser stayed up, the account stayed connected, and the other things that use the same browser carried on normally, so from outside there was nothing at all to see.

Found by comparing two installations running different versions: both stopped claiming within ten seconds of each other and stayed stopped for ninety-five minutes, seven healthy monitors each, while the account poller went on using the same browser every two minutes. Reproduced on purpose afterwards by restarting one: it took its three direct sources, opened the notifications tab, and never came back.

## What was hanging

Reading a timeline means asking the page for its contents and waiting for the answer. A page that has stopped answering never answers, and that request had no time limit of its own. The error handling on it looked like it covered this and could not: a request that never comes back never fails either, so nothing that was waiting for a failure ever ran.

Both halves are fixed:

- **Reading a page now gives up after fifteen seconds.** The work involved takes milliseconds on a page that is answering at all, so anything near that limit is not slow, it is gone.
- **A poll now gives up when it outlives its own turn.** That is not a new setting: it is the moment the source becomes available to be polled again anyway, so a poll still running then has already overrun by definition.

The second is the one that matters most. Whatever stops answering next, the radar keeps running.

## And it says so

A source that had to be given up on is shown amber, with a sentence saying it stopped answering part-way through and that nothing was read, which is not the same as nothing being there. It backs off, keeps its place in the timeline so nothing is skipped, and tries again.

That distinction is the whole point of the release before this one, and this fault was quietly defeating it: the radar was reporting seven healthy monitors because the code that would have marked them unhealthy was never reached.

## Nothing else changed

No behaviour has been added or removed here. An ordinary poll is untouched and the time limits are invisible unless something is genuinely wrong.
