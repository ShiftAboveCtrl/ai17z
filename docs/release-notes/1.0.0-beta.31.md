**Two things that were wired to almost nothing.** Beta 4.0 went looking for places where two parts of AI17Z should have been talking and were not. These are the two it found after it shipped, and both were visible only by reading rows on a real account.

## A goal your agent can actually work on

You can give an agent something to work on, and AI17Z has always used it: a post that bears on one of your goals is worth twenty-five points of attention, and that is frequently the reason the agent looked at something at all.

It then threw the answer away. The part that scores an observation knew which goal it related to; the part that stored the result was handed only the words, never which goal they belonged to. So nothing was ever recorded against a goal, and the function written to do it had never once been called outside a test.

**A goal now collects what the agent found bearing on it**, and the Mind screen shows it. Once per subject rather than once per sighting, because three people saying the same thing is one finding, and an agent whose goal rests on twenty copies of one post looks like it is fixating.

The percentage on each goal is gone, and this is the more embarrassing half. Nothing in AI17Z could move that number. The one function able to change it accepted the value, the address that called it did not pass it on, and the screen never called that address at all, so every goal on every installation showed a progress bar stuck at zero for as long as it existed. The screen also said the agent "can work on them", which was not true either. It now shows what the agent has found, the bar appears only where a number was actually set, and how far along something is stays your judgement. Nothing the agent does decides that, for the same reason nothing about what it pays attention to is left to a model: an agent scoring its own progress is marking its own homework.

## One post, one like

An agent that decides to like something records that intention as a job, so it is as traceable as a reply. Beta 3.9 fixed that job being run a second time by the ordinary worker, and part of that fix was making one post one target however its address was written.

That fix was half of it. The two parts of AI17Z that can write a "this action already happened" marker were still spelling it differently: one included which capability was being used and which post, the other included neither. Two spellings that can never match, so the uniqueness check that exists to stop an action happening twice had nothing to compare. On a real account that is exactly what happened, before the earlier fix landed: two posts were each liked twice, four minutes apart.

The earlier fix closed the ordinary route and left a note saying a crash partway through was safe because this marker would catch it. It would not have. **It does now**, and a test holds the two spellings against each other so they cannot drift apart again.

Replies and posts are deliberately untouched. Only one part of AI17Z writes those, so there is nothing for them to disagree with, and changing them would strand work already queued when you upgrade.

## Also

The deliberation document now says what an agent may and may not do with a goal, which was true before and written down nowhere.
