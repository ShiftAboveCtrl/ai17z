**Beta 1.0.0 could not be used. Take this one instead.**

AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

## The black screen

Opening AI17Z showed the interface for an instant and then went black, on every installation, every time. Nothing was wrong with anybody's data — the fault was entirely in the interface.

A React hook sat below an early return in the agent list. React counts hooks by call order, so the first render called seven and the second called eight; React answers that by throwing during render and unmounting the whole page, which leaves an empty document over the application's own near-black background. Hence a black rectangle with no message in it.

Fixed, along with the same mistake in the agent's Identity section, which would have done the same thing the moment an agent gained its first persona version.

## Upgrading did not run the code it installed

Found while proving the fix, and worse than the fault it was hiding.

`docker compose up -d` builds an image only when one is *missing*. It has no idea the source changed, and AI17Z only rebuilt when explicitly asked. The Docker project name comes from your data directory, which an upgrade deliberately does not touch — so every image from the previous version was still there under the same name, and still started.

An upgrade therefore served the old application. You would have downloaded this fix, run the installer, launched AI17Z, and seen exactly the same black screen, with nothing anywhere saying why. Uninstalling and installing again would not have helped either.

Every image now records what it was built from, and starting AI17Z compares that against the code that is installed. If they differ it rebuilds, and says why it is doing so. Every way of not knowing — no label, no image, Docker silent — ends in a build, because building unnecessarily costs a few minutes and not building costs the whole release.

**This applies to you if you are on Beta 1.0.0.** Install this over the top and launch it: the first start will rebuild, which takes a few minutes and prints what it is doing. Nothing else is required.

## Three checks that were reporting success without looking

The reason a one-line mistake reached a published release.

- **The installer gate fetched the interface and checked for HTTP 200.** That is nginx handing over an `index.html` with an empty div in it, which is just as true of an interface that crashes the instant it runs. It now creates the owner account, signs in through a real browser, and waits for the agent list to draw — and it does the same again after an upgrade, and fails if the images did not move to the version that was installed.
- **The release tooling was not typechecked.** The gate, the packager and the secret scan — the three things that decide whether a release ships — were outside the TypeScript project.
- **There was no error boundary anywhere in the application.** That is why the mistake became an unreadable screen rather than a message. Any render error now shows what broke, where, and a way back. A test also walks every component and fails on any hook an early return could skip; it found the second occurrence on its own.

## Everything from Beta 1.0.0

That release could not be run, so its changes are listed again here.

**Move an agent to a new machine without re-typing your keys.** A MOVE package can now carry the provider API keys the agent's models use — only those, never every credential in the installation. Off unless you ask for it, refused outright on a SHARE package, declared before you import, and named `-with-keys-SECRET` so you notice it in a folder listing. The file holds them in the clear because a key sealed under the master key of the machine it is leaving is useless on the machine it is arriving at; import re-seals them under the receiving installation's own key.

**The installer looks for AI17Z before offering to install one.** It reads the registry and the usual directories, lists what it found, and asks whether to update that installation or set up a second alongside it. On an update it skips the questions it already has answers to.

**Ports pick themselves.** It walks up from the default until it finds a free one, so the common case is pressing Next. The boxes are still there if you want them.

**Releases have names.** This one is *AI17Z Beta 1.0.0 (2)*. The tag is still the number, which is what decides what is newer.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely — off means no request is made at all.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched.

## Verifying the download

```powershell
Get-FileHash .\AI17Z-Setup-1.0.0-beta.2.exe -Algorithm SHA256
```

Compare against `SHA256SUMS.txt`. The installer is not code-signed yet, so Windows SmartScreen will warn about an unknown publisher.

## Known limits

- **Windows is the verified platform.** The Linux scripts are written and syntax-checked, but nobody has taken a clean Ubuntu machine through the flow.
- **Headless servers are not a supported flow.** Connecting an X account opens a real Chrome window for a person to sign in to.
- **One X account has been run end to end.** Two agents in one installation and two installations on one machine are both tested; two signed-in X accounts side by side are not.

## Requirements

Windows 11, Docker Desktop, Node.js 20+, and Google Chrome. The installer detects what is missing and tells you; it does not bundle them.
