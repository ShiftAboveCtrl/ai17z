**An installation can no longer serve one release's code over an older release's dependencies without saying so, and an account read stops calling every reply an announcement.**

- **Found on two real installations running Beta 7.1.** Both reported the current version on every screen while their API containers were serving a dependency that the release before had already replaced to close five advisories. The source in the images was current; only the dependencies were old, and nothing anywhere said so.
- **Why nothing caught it.** An image carries a label saying which source it was built from, and that label is written from the installed version whatever the build actually reused. It records what a build meant to do, not what came out of it. AI17Z now reads the dependency lockfile back out of the image and compares it with the one the installation ships, which a label cannot be wrong about.
- **If a rebuild does not fix it, AI17Z says what will.** Docker can keep serving a stale copy of the program folder to its own builder, through an ordinary rebuild and through a cacheless one alike. Clearing the build cache is what fixes it, and AI17Z names that rather than doing it, because it would throw away every other project's build cache on the machine.
- **All three platforms, one check.** Windows, Ubuntu and macOS had the same gap because they have the same shape.
- **An account read counts replies again.** Reading somebody's recent writing is meant to show how much of it is conversation rather than announcement. When the reader fell back to the rendered page, where a reply shows who it answers but not which post, every reply and every quote was counted as an announcement instead. Five accounts read one after another, one of them an agent that does little else but answer people, all came back as nought replies.
- Everything in Beta 7.1 is included.
