**Agents can now think between the things they are asked.** Until this release an AI17Z agent was reactive: it answered what it was asked, and when nobody asked it had nothing to say — so a posting schedule either went quiet or produced filler, and every reply started from the same standing start however long the agent had been running.

**This release also finishes the X reading work**, so everything that reads X now reads it from one place, and closes a defect that could quietly cost you a signed-in browser session.

---

## An agent with a present tense

An AI17Z agent already had identity, persona, voice, six memory scopes, relationships, stances and commitments. What it had never had is a record of what it is interested in *now*, what it is unsure about, what it is trying to find out, and what it recently learned.

There is a new **Thinking** view in X Studio. It shows what is on an agent's mind, what put it there, what it is trying to do, and every time it looked — including the times it found nothing.

**It is off by default.** An agent does not start thinking because it was created. When you turn it on there are four rungs rather than one switch, because "autonomous" is four separate decisions people make at different times:

| | |
| --- | --- |
| **Watch** | Notices what happens and scores it. Changes nothing, says nothing. |
| **Think** | Also reflects and keeps track of what it is interested in. |
| **Suggest** | Also puts ideas in the backlog for you to look at. |
| **Act** | Also lets those ideas reach the same policy, cadence and approval gates everything else passes. |

**Act is not a bypass.** It decides whether a candidate is *offered* to the engagement heuristic, the policy gates, cadence, rate limits, idempotency and exact-target verification — never whether those run. **Pause All stops the thinking too**: it costs model calls and changes the agent's own state, and somebody who pressed pause did not mean "keep developing opinions".

### What it shows you, and what it will never show you

Every item is a conclusion, the evidence it rests on, and how sure the agent is. **No raw model reasoning is stored anywhere, shown to you, or sent to X.** A "reflection" is a durable summarised artifact; it is not a transcript.

Deciding what is worth an agent's attention is deterministic — no model call — because *"the model thought it was interesting"* is not a reason you can inspect, correct or tune, and that is the judgement you most need to be able to look at. Every point on the screen carries a sentence: what subject it is about, whether it bears on a goal, who said it, how fresh it is, whether anybody else was discussing it.

**Most of what an agent sees is declined outright** rather than scored low and kept. Having nothing to do with something is a reason not to think about it, not a weak reason to think about it — an agent whose working set fills with everything it saw has no interests, it has a queue.

### Doing nothing is a result

Most times an agent looks, it finds nothing. That is recorded and shown as what happened, because a view that listed only the productive runs would make a correctly quiet agent look broken. A quiet agent also backs off, so it stops asking a paid model the same question every half hour for ever.

### What reaches a reply

Only what is relevant to what is being said. An agent may be uneasy about something all week without every answer mentioning it — internal state that leaks into unrelated conversations is worse than internal state nobody has, because it reads as an agent that cannot tell what it is talking about.

An original post is the exception, because there is no incoming message for anything to be relevant *to*. Confidence travels with each line: a hypothesis held at 0.4 is introduced as a thing it suspects, not as a finding.

## Following a project

An agent whose subject is a piece of software and which has no idea what shipped in it can only repeat what it was told once. You can now point one at a repository, and it will know what the project actually did — with a link you can check on every fact.

Public repositories need no credential at all. A private one takes a read-only token, sealed under your master key exactly as a provider API key is.

**It is read only, and structurally so**: four GET endpoints, and no push, merge, comment or release anywhere in it.

**Most of what a repository does never reaches the agent.** A typo fix is not a post. Conventional `chore`/`ci`/`docs` prefixes, lockfile bumps, a subject too terse to be about anything, a pull request that is only proposed, a build doing what builds do — all declined. A release always counts. A red build counts, because somebody may ask.

Two new capabilities, `github.read_activity` and `github.read_release`, answer out of what AI17Z recorded and **never call GitHub**. So a model cannot make your agent hammer somebody else's API by asking the same thing in a loop, and what an agent can say about a project is exactly what you can see on the screen. Release notes are returned as published, and a release AI17Z has not read is answered with that rather than approximated — a plausible invented changelog is worse than an admission.

## Stopping AI17Z could lose your signed-in browser

Chrome runs as a child of the worker, and the worker was stopped with a tree kill. A force-killed Chrome may never flush its cookies and local storage — which is the entire signed-in X session that profile exists to hold. Getting it back costs you a sign-in and, on an account with two-factor, your phone.

Every other path in AI17Z closed Chrome properly first. **"Stop AI17Z" from the Start Menu — by far the most common way an installation is stopped — went straight to the kill.** It now asks the worker to close the browser and waits, bounded, before stopping anything. A browser that does not answer is not allowed to become an installation you cannot stop, so it says so and stops anyway.

## Everything that reads X now reads it from one place

The canonical X reading layer landed last release and almost nothing used it. The radar's searches, the model's own X capabilities and the growth screens all still scraped rendered pages.

A drawn article carries neither the author's numeric id nor an exact engagement count, and both absences travelled the whole way down:

- **Relationships could only be keyed on a handle.** Somebody who renamed themselves became a second person — the exact discontinuity the relationships table exists to prevent.
- **The opportunity engine had weighed crowded and empty threads since it was built**, and nothing had ever been able to give it a reply count.
- **Bridge scores reported reach and reciprocity as permanent gaps**, because filling them meant reading a profile per card.

All three are closed. `x.read_post`, `x.read_thread`, `x.read_profile` and `x.search` now read X's own data, so they return immutable ids, exact counts and the real reply chain — with the rendered page still underneath as the floor.

Falling back stays a decision rather than a reflex. A changed API is worth another reader; a protected account, a security check or a rate limit is not, because loading the same page again after a rate limit is how a read turns into hammering.

## X Studio: People

A new screen for who an agent knows. Three things kept deliberately apart: what has passed between you, where their attention leads, and what their account says.

Reading somebody is an action you take, not something a card does when it appears — a screen that read X to fill in a hundred cards would cost a request per card against the session your agent needs for its own work.

**What their account says never becomes what you discussed.** An agent's relationship topics render in a prompt as "you have discussed…", so filling them from somebody's public timeline would have an agent open by referring to a conversation that never happened.

`x.read_account` is gone. `x.read_profile` did the same job through the same layer and returns a typed profile rather than a block of text, and two switches for one decision is a switch somebody turns off expecting something else to stop. What it had that the other did not — reading more of somebody's posts — moved across as an argument.

## Smaller things

- The installer verifier compared an installed database against the repository's migrations rather than the ones the installation shipped. They agree right up until somebody edits the repository while a run is in progress, and then it failed an installation that was perfectly correct.
- Narratives now count distinct people rather than distinct names, so somebody who renames themselves mid-window is one voice instead of two — and "several accounts are saying this" is the only thing separating a narrative from a loud account.
