A correction to [Beta 1.0.0 (17)](https://github.com/ShiftAboveCtrl/ai17z/releases/tag/v1.0.0-beta.17), which is the release that brought macOS and Ubuntu. Everything it says about installing on those platforms still holds — this fixes something it claimed about **updating** that was true only on Windows, and two messages that sent people to look in the wrong place.

**If you are installing AI17Z for the first time, install this one.** The commands are unchanged.

---

## What was wrong

Beta 1.0.0 (17)'s release page says:

> An installation made before that check existed keeps its old behaviour; a current one whose check cannot run **refuses to update** rather than pressing on and finding out afterwards.

That was true on Windows. It was true of neither macOS nor Ubuntu.

The compatibility check itself worked everywhere: an update that a machine genuinely cannot run was refused, and nothing was stopped or replaced. What did not work was the **other** half — what happens when the check itself cannot run at all. On macOS and Ubuntu that carried on regardless, and said so:

```
This installation predates the compatibility check; continuing.
```

to a copy installed that morning, of the first release that could be installed on either platform, which shipped the check inside it.

The reason is small and the shape is worth knowing. An installation says which version of the update protocol it speaks in a file called `INSTALL_INFO.json`, and **neither Unix installer ever wrote one**. Nothing recorded meant "older than the check" — which is right on Windows, where such installations exist, and impossible on macOS and Ubuntu, where none can.

Found by installing the published `.deb` and looking, rather than by reading the source.

## What this release does about it

On macOS and Ubuntu, an installation that cannot say which protocol it speaks now **stops** rather than guessing. Where the check can be asked at all, it is handed the protocol version the installed application actually carries, read out of that application rather than written down a second time in a shell script.

The practical difference: if something is wrong with an installation on those platforms, updating it now refuses and leaves the version you have installed and running — which is what the previous release said it would do.

Windows is unchanged, deliberately. There really are Windows installations older than the check, and refusing those would strand exactly the copies it exists to move forward.

## Two messages that pointed the wrong way

Both found by running the published command rather than reading it.

**A refusal blamed your connection when GitHub had refused the request.** GitHub allows sixty API requests an hour to an address that is not signed in, and a shared office, a university or a cloud machine reaches that without anybody doing anything unusual. The command said `403 Forbidden` and then told you to check your internet connection — the one explanation that was definitely wrong. It now says what a 403 usually means and that waiting a few minutes is the answer. On macOS and Ubuntu, where the status cannot be recovered, the wording no longer picks a cause it cannot know.

**A named release that does not exist is now said to not exist.** `-Release v0.0.0-nope` used to answer "AI17Z could not work out which release to install" and send you to check your connection. It worked out which release perfectly well.

**And a line named a file that a clean install deletes.** "Reading it afterwards: …" pointed at the checked setup program, which is removed when an install finishes cleanly — so anybody who went to read it found nothing and had no way to know that was correct. It now says where the file is while it runs, that a clean finish removes it, and that `-KeepDownload` keeps it.

## Everything else

Unchanged from Beta 1.0.0 (17): Windows, macOS on Apple Silicon and Intel, Ubuntu 22.04 / 24.04 / 26.04 on amd64 and arm64, each package built on a machine that really is that architecture. Installation commands, paths, data locations and security posture are all the same.

One addition behind the scenes: a published release is now installed again **from its own URLs**, on real Macs and real Ubuntu machines, by a run that takes nothing from the build — and that run is started by the release itself, because a release created by a workflow raises no event another workflow can listen for. Beta 1.0.0 (17) found that out by being published and watched.
