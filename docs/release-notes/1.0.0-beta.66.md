The shared utility surface: one signed endpoint that lets a website caller
reach this runtime's canonical trading engine, without installing AI17Z.

## What it is

`POST /api/utility/invoke`, with an HMAC-SHA256 signature over the timestamp
and the exact request bytes, and `GET /api/utility/capabilities` for what the
runtime can actually do. Three capabilities, each with a schema: a paper trade,
a paper portfolio, and a market snapshot.

Behind it is **core's own paper engine**, not a copy. The mandate, the market
read, the risk gate, the quote, the simulation and the journal are all this
runtime's, and `runPaperTrade` forces `mode: 'PAPER'` here rather than reading
a mode from the request. There is no argument that makes it live.

## Why it does not need confidential hardware

Everything on this surface is public, moves no value, and holds nothing anybody
would mind losing: no provider credential, no wallet, no browser session, no X
cookie. That is what makes one runtime able to serve many callers, and why none
of this is waiting on the attestation canary. A persistent secret-bearing agent
is a different tier and still is.

## The caller is a pseudonym and stays one

The gateway sends an opaque string rather than a person, so this runtime cannot
learn whose request it is running. It keeps a separate agent, mandate and
journal per pseudonym, so two callers' paper trades are as separate as two
agents on one owner's machine. Proved rather than asserted: two pseudonyms
produce two agents, and a caller who has traded nothing sees nothing rather
than seeing somebody else's trades.

## What it refuses, and why each one is there

- **An unknown field in a request body** is refused rather than ignored, so a
  caller sending `mode: "LIVE"` fails loudly instead of having it dropped while
  they believe otherwise.
- **An amount is a string of base units**, never a number: at eighteen decimals
  a double cannot represent one base unit of difference.
- **A replay** fails, because the signature covers the exact bytes and the
  timestamp, and the window is two minutes. The signature length is compared
  before its contents, because `timingSafeEqual` throws rather than returning
  false on a mismatch and a thrown comparison is a 500 where a refusal belongs.
- **A missing signing secret** answers 503, not 401. That is this runtime
  failing to be configured rather than a caller failing to prove anything, and
  a 401 would send an operator to check a key that was never the problem.
- **`asset.resolve` is not offered at all.** There is no asset resolver in this
  build, and a capability with no handler is one somebody discovers is a stub by
  calling it.

## It says what it cannot price

`GET /api/utility/capabilities` reports readiness per venue, with the reason,
plus one word for whether anything can be priced at all. Without that, a caller
submits a paper trade, waits, and gets `NO_MARKET`, which reads as the product
being broken rather than as the runtime having no market data provider.

**On a runtime with no provider installed, nothing is priceable**, and it says
so for all six venues. That is the honest state: only the `MarketReader`
contract and test readers exist, and a production reader needs an RPC endpoint
and verified venue addresses, neither of which is in this repository.

## Proved against a real caller

Both halves had tests against something implementing the other's contract,
which cannot prove the two agree. So a second API was run with a signing secret
and called by the real client: the signature verified, a smuggled `mode: LIVE`
was refused over the wire by the strict envelope, an unknown capability was
refused, and a paper trade reached the engine and came back with "No market
reader is installed for Pons V2 (curve), so it cannot be priced" rather than a
made-up price.
