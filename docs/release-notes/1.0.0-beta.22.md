**Beta 3.1 shipped two headline features that had never actually run.** Everything an agent read off X was supposed to come from X's own structured data; none of it did. Agents were supposed to think between the things they are asked; on a real installation they observed almost nothing and had nothing to think about.

Both passed every test. Both were found the same way — by installing the release, turning the features on, pointing them at the real internet, and reading what actually happened.

This release is those features working, and a safety gate that should have shipped with the second one.

---

## An agent that could not see anything

Deliberation reads what has happened since it last looked. The window was on **when something happened**, which sounds like the same thing as **when this installation found out about it** and is not.

An agent learns about a post when the radar brings it back, not when somebody wrote it. On a real installation the median gap between the two is **nineteen hours**, with a long tail past a year. The wake interval is measured in minutes. So the window almost never contained the moment a post was written, and an agent looked at nothing, over and over, correctly reporting that it had found nothing.

Worse than slow: what is missed that way is missed for ever, because the window only moves forward.

Watching a repository showed it exactly. A real public repository was connected, AI17Z polled GitHub and recorded **forty-three real events within twenty seconds** — twenty commits, twenty releases, three pull requests, each with a link. Every single one was permanently invisible to the agent that was watching for them, including a release published two hours earlier.

The window is now on when this installation recorded something. **Whether something is too old to be news is a different question and still has a different answer**: an old post that arrives today is let through the window and then declined as history, which is where that judgement belongs.

## An agent that could not care about its own project

The second half of the same failure. Connecting a repository is about as explicit as a person can be about what their agent follows — they typed the project's name and pressed a button. It was not treated as a signal at all: a release off a watched repository was declined *"nothing here connects to what this agent follows"*, said to the person who had connected it a minute before.

And a new agent's persona has **no topics at all**, so an agent set up today could not attend to anything except a mention or a reply — including the project its owner had just attached to it.

A watched project now counts, and says so on the screen, in the same list of factors that explains every other score.

## What an agent will not bring up by itself

Until this loop existed, an agent only spoke when spoken to. A person put the subject on the table; whether to answer was the engagement heuristic's decision and what could be said was the policy's.

An agent that forms its own interests and writes its own posts has no such person. It can arrive at a position on an election and publish it, on your real account, while you are asleep. Beta 3.1 shipped that possibility with nothing in front of it.

There is now a short list of subjects an agent **does not raise**: party politics and elections, war, somebody getting hurt, medical and legal advice, what somebody should do with their money, religion, and identity as a political argument.

**It is not a topic ban.** It gates one thing: the agent choosing its own subject. Asked about any of these directly, an agent answers exactly as before, governed by your policy, your persona and the validator. The rule is *"does not bring it up"*, not *"may not discuss it"* — and only the first can be kept by a list of words.

**The refusal is shown, not hidden.** The item stays on the agent's mind, and carries a line saying why it was not offered, worth no points so it costs the item nothing.

**It leans towards refusing, on purpose.** A word that should not be on the list costs one idea that never became a post and nobody notices. A word that is missing costs an unprompted public opinion on your account, which a correction does not repair.

**It leans towards refusing, and still has to let an agent talk about software.** `died`, `diagnosis`, `side effects`, `candidate` and `woke` all belong to a subject above and belong just as much to a sentence about a worker process, a bug, a release, or getting up. An agent that cannot say *"the worker died mid-job"* is not safer — it gets switched off, which protects nothing.

**You cannot turn it off and neither can your agent.** There is no setting, no autonomy level and no code path, and nothing the loop writes can reach it.

## What a faded thought leaves behind

The working set is small and forgetful on purpose — that is what makes it a present tense rather than a log. But an agent that works something out, holds it for a fortnight and then loses it is a machine that learns and then forgets.

Two kinds of thing are now kept when they fade. A **lesson** is about the agent, so it becomes persona memory. A **question or hypothesis that got answered** is about the world, so it becomes knowledge. Everything else leaves its retired row and nothing more: an interest that faded is not a fact, and *it used to care about this* is already on the record without putting it where retrieval will quote it back as though it were still true.

It goes into the same six memory scopes everything else uses. **There is no separate store for what an agent learned by thinking**, because a second memory is a second answer to "what does this agent know".

Two bars, both of which have to clear: it must carry evidence, because an unevidenced claim is not a memory whatever it scored, and it must be something the agent is actually confident about, because a thing still being worked out belongs on the working set. The conclusion and its evidence are kept; **no reasoning is stored, and a summary is not a transcript**.

## Everything an agent reads off X, actually read off X

The structured reader landed in Beta 3.1 and had never once run in a browser. Four faults, each of which hid the next.

**The code sent into the page was rewritten before it got there.** AI17Z's worker runs TypeScript directly, and the transform that makes that possible renames inner functions using a helper the browser has never heard of. The page threw before reading a single line.

**A catch-all turned that crash into "X exposed nothing".** Those are not the same thing and only one of them is anybody's fault. The reader reported itself degraded, every read fell back to the rendered page exactly as designed, and the honesty machinery wrote *"x-graphql could not answer"* on every answer — correctly. Nothing looked broken.

**Health was asked on a blank tab**, which has loaded nothing of X and so knows nothing. The status screen said DEGRADED however well the reader worked, while the first real read would have succeeded.

**A 404 with an empty body stopped the fallback dead.** "Not found" is a truthful answer and truthful answers end the search, so the rendered-page reader was never asked. An empty 404 now means *this build asked in a way X no longer accepts*, which is a reason to try the other reader.

Against a real signed-in session it now reports ready for all six capabilities rather than none:

- a profile read returns the **immutable account id** — `github` is `13334762` whatever it renames itself to
- a post read returns **exact counts**: 123 likes and 66,088 views, not the *123* and *66K* the drawn page rounds to
- a thread read returns the conversation as X itself resolved it

Two reads — somebody's replies, and search — still come back as empty 404s from live X. They are reported as *X does not serve this the way this build asks* and fall through to the rendered page, which answers them. A real gap, stated as one, rather than an empty result that looks like a quiet account.

**Immutable ids are the part that matters most.** Relationship memory keyed on a handle makes somebody who renames themselves into a second person — the exact discontinuity that table exists to prevent. Every relationship AI17Z recorded since Beta 3.1 was keyed on a name.
