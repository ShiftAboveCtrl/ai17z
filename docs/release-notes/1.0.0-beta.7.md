AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

## Two installations are now actually two installations

Installing a second copy of AI17Z alongside one you already had gave it its own data folder and its own ports — and then handed it the first copy's program folder, Start Menu group, desktop icon and entry in Add or remove programs.

That is not cosmetic. The program folder holds a single pointer to the data folder, and every shortcut follows it. So installing a second copy silently repointed *both* shortcuts at the second copy's data: the browser worker served one installation while the other reported that nothing could open a browser, and neither shortcut did what its name said.

**The installer now asks what to call this installation** — once, and never on an update. That one name becomes the program folder, the Start Menu group, the desktop icon and the uninstall entry, so Windows can tell two copies apart. Leave it as `AI17Z` unless you are installing a second copy alongside one you already have.

An installation already called `AI17Z` keeps the identity it has, so updating over it replaces it rather than installing a second one beside it.

## Starting AI17Z stopped guessing whether a worker was running

The launcher decided whether a browser-capable worker was already running by reading a process id from a file and asking Windows if that process existed. That was wrong three ways, and on a machine with two installations all three arrived together:

- the recorded id belongs to the wrapper that starts the worker, not the worker. The worker can be gone while the wrapper is still alive
- process ids are reused, so something unrelated answers to the number
- and an id says nothing about *which* installation a worker serves

The result was a launcher reporting "native worker already running" while AI17Z itself said nothing was there that could open a browser. Both were true statements about different things.

It now asks the database — the same heartbeat the interface reads — so the two can no longer disagree. And "could not ask" is treated differently from "there is none", because starting a second worker over a database that briefly blinked is worse than leaving one out.

**A second installation can now run its own browser worker.** There was a check refusing to start one if any other AI17Z already had, which was right within a single installation and wrong across two: they hold different accounts, in different databases, with separate browser profiles.

## Everything from Beta 1.0.0 (6)

**Your agent was watching one surface out of five.** A connected X account had only its notifications page being read; the four monitors that search — for your handle, for replies to it, and under your own posts — had nothing telling them to run. A new X account now gets all four, and an existing one repairs itself on Start.

**And turning a monitor off never worked.** A unique constraint over a column that could be empty never collided, so saving a monitor as disabled wrote a second row and left the original running. The setting looked applied and did nothing.

**An imported agent can be started**, the model is a list, pasting a key names its own provider, and Google Gemini is supported.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched. The first start after an upgrade rebuilds and says so.

## Verifying the download

```powershell
Get-FileHash .\AI17Z-Setup-1.0.0-beta.7.exe -Algorithm SHA256
```

Compare against `SHA256SUMS.txt`. The installer is not code-signed yet, so Windows SmartScreen will warn about an unknown publisher.

## Known limits

- **Windows is the verified platform.** The Linux scripts are written and syntax-checked, but nobody has taken a clean Ubuntu machine through the flow.
- **Headless servers are not a supported flow.** Connecting an X account opens a real Chrome window for a person to sign in to.
- **Two signed-in X accounts side by side** are now covered by the release checks, which install two copies at once and use both. Two accounts inside one installation remains untested.

## Requirements

Windows 11, Docker Desktop, Node.js 20+, and Google Chrome. The installer detects what is missing and tells you; it does not bundle them.
