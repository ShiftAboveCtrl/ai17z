**Hosted AI17Z: the runtime a customer would rent, built and measured, with the one thing it waits on named rather than glossed.**

- **An AI17Z runtime now runs inside its own virtual machine, and two of them run at once.** A microVM boots under the jailer as an unprivileged user with its own kernel, its own network namespace and its own disk, and the canonical AI17Z runs inside it: Postgres in the boundary, its own database, all 106 migrations, the api answering its own health endpoint, the worker ready. Two tenants run side by side with separate keys, separate databases, separate disks and separate users, and neither can reach the other's runtime while that runtime is answering its own tenant. Six run at once at about 531 MB each, with nothing degrading between the first and the sixth.
- **The lab boots what AI17Z itself renders, and that change found two real faults.** It used to boot a configuration written in a shell script, which proved that Firecracker works and nothing about this program. Pointing it at the plan the code produces found both within a minute: every path after the jailer's separator is inside the chroot, so a kernel named by its path on the host could not be opened at all; and both tenants were running as the same user, which the code's own rule had always refused, because one process can signal and inspect another running as the same user.
- **A tenant survives being killed as hard as a power cut.** It comes back with its database cluster, its schema, its state and the same key. Finding that out also corrected a measurement that had gone the dangerous way: the first reading said the tenant had lost everything, and it had lost nothing, because the tool used to check a filesystem cannot replay its journal when it is opened read-only. A durable system measured as lost is not a safe mistake to make quietly.
- **A tenant's disk now honours a flush.** The default ignores them, which means a transaction the agent is told was committed is on no disk after a host crash, and the guest cannot tell either: it reports the device as needing no flushing at all. Both halves of that are fixed and a test fails if either returns.
- **A tenant's master key survives a restart.** It was being generated fresh on every boot, so everything sealed under the previous one became unreadable: provider credentials, account credentials and plugin secrets all at once. Two boots of one tenant produced two different keys, which is a measurement rather than an argument.
- **What hosting would cost is computed rather than recited.** The confidential machine prices are data with the date they were read on, and the floor is worked out from them and from what a tenant was measured to need: about $63 a month on demand, and roughly $38 to $90 once region and commitment are allowed for. The figure that decides the shape of any plan is not about AI17Z at all, which is that the floor is set by the smallest confidential machine anybody sells rather than by what a tenant needs.
- **The thing it waits on is said plainly.** Everything above runs on ordinary hardware, where tenants are isolated from each other and not from whoever administers the machine. Confidential hardware is what changes that, and none has been provisioned: the attestation checking, the measurement policy, the key-release design and both cloud adapters are built and tested, and the adapters render the request they would send rather than pretending to send it. Phase 1 is frozen as a candidate with that canary outstanding, which is the only honest status available.
- **Nothing is for sale, and that is deliberate.** The offer would be that whoever runs the machine cannot read your agent, and until that has been proven on real hardware it would not be true.
