**The same omission, in the second of two lists.** Beta 5.3 exempted the release notes from the checksums and not from the provenance check, so the release published correctly and was rejected again by the same step, for its other half. This corrects that and pins both lists to an exact set.

## What a published file owes

Two separate things, decided in two separate places.

A line in `SHA256SUMS.txt`, because the command and the setup program will not unpack a payload whose hash they cannot establish. And an attestation, because a release that claims build provenance while its assets have none is a claim that stopped being true without anybody noticing, which has happened here before.

Both are waived for the same small set, and for one reason rather than two: the files published straight from the checkout instead of made by a build job. A file no build produced is a file no build attested, so asking whether it is attested can only ever be answered no.

Measured against the previous release: the notes returned HTTP 404 with no attestations, while the manifest, the checksums and the application package each had one. That is the whole failure, and it is what the exemption is for.

## Why this took two releases rather than one

The first correction was right and incomplete. It fixed the list it had just been shown and did not look for the other list governing the same file, so the next release was published, tagged and rejected in the same step for the other reason.

The test that came with it had the same blind spot: it compared the published assets against the hashed names and the checksum exemptions, and never read the provenance skip at all.

It reads all three now, and holds the attestation waiver as an exact set rather than a minimum. Widening it is a decision somebody makes in a failing test, which is where this should have been decided both times.

## What has not changed

The checksums still cover every installable payload, every built asset is still attested, and what is verified before anything is installed is exactly what it was. The two files this exempts are read, not unpacked, and one of them is allowed to be missing entirely.
