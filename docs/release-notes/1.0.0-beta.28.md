**One defect, found by letting an agent act on its own choice on a real account and then reading the rows.** If you have not turned an agent up to **Act**, this changes nothing you can see. Everything in Beta 3.5, 3.6 and 3.7 is here too.

## An agent's own like was being carried out twice

When an agent likes or reposts something it chose, AI17Z writes a job for it, so the like is as traceable as a reply and the history has one shape.

A new job is work the queue can pick up, and it was picking it up: while the like was still being performed, the ordinary worker claimed the same job and ran the whole pipeline on it. Context, memory, a model call, a validation pass, and a second attempt at the same action.

Measured the first time an agent acted on its own choice: four decisions, four jobs, every one of them run twice, and six model calls spent drafting a reply for an action that has no words in it.

The record is now held out of the queue from the moment it is written, and settled as soon as the action finishes. Nothing about what your agent decides, or how it is gated, has changed.

## One post is one post, however it is written

The duplicate should have been stopped by the ledger that exists to stop exactly this, and was not: it keys on the target, and one path carried a post's id while the other carried its address. Two spellings, two targets, no collision to detect.

A target AI17Z recognises as a post is now reduced to its id first. One it does not recognise is left exactly as it came, because guessing at an unfamiliar target would turn two genuinely different actions into one, which is the worse mistake: a duplicate costs a wasted call, a collision costs an action that never happens.

## Why this was not caught before

Every test of the autonomy ladder stopped at a refusal, because the test fixture never granted the agent permission to like anything. The path that acts had no coverage at all. It does now, and the test would have failed on this.
