**The Plugins page sat under the navigation and showed most of your capabilities, not all of them.** Both are fixed. An ordinary question also stops paying for a planning step it did not need.

## The Plugins page clears the navigation

Opening Plugins put its own title behind the top navigation. The page had invented its own layout instead of using the one every other top-level page uses, so it started 35 pixels too high.

It now uses the same page shell and the same heading as Home, Activity and Settings, which is what makes it clear the navigation and what makes it look like the rest of the application rather than a screen added afterwards.

Fixing it turned up the same problem on a narrow window, where the navigation wraps to two rows and becomes taller than the space every page left for it. That is corrected across all of those pages, not only this one.

## Every capability is now reachable

Plugins grouped the capabilities into six named groups and showed only those. Three capabilities belong to no group — checking the time, searching the agent's own memory, and reading its own health — so they were not on the screen at all. The only place to manage what an agent can reach for was managing most of it.

There is now an **All capabilities** tab listing every one of them, with the three that belong to no group shown plainly as Core rather than filed under an invented seventh group. You can:

- search by name, id or description
- filter by group, including Core
- filter to reads or writes
- filter to on or off
- filter to ready or not ready yet

Each row shows which group holds it, whether it is permitted, whether it can actually run and why not when it cannot, and how often it has been used recently. The switch is the same one the rest of the product writes, so nothing here is a second opinion about what your agent may do.

## An ordinary question is quicker

Before replying, AI17Z can ask a small model what is worth looking up. That step was triggered by anything containing a question mark, including questions about the agent itself. "How long have you been running?" spent a model call to be told, correctly, that there was nothing to look up.

It now runs where it can change the answer: when there is an image or a link, when the ordinary rules already found something worth looking up, when the question names something checkable, or when a short question sits under a post, because the post is the subject and the rules cannot read it.

Measured on a real installation against its own models, across three passes of a fixed set of messages:

- simple questions: two model calls became one, median 6.9s to 5.1–6.7s
- questions answerable from memory: two calls became one, median 3.1s to 1.8–2.4s
- opinions: two calls became one, median 4.2s to 3.2–3.5s
- questions that genuinely need looking up: unchanged, still plan, still research
- model calls across the whole set: 45 to 33–35

The slowest tenth of replies is unchanged, because those are dominated by the reply itself rather than by the planning step. Nothing was removed from what an agent knows or checks: the ordinary rules still decide what to look up, exactly as they do when no planning model is configured at all.
