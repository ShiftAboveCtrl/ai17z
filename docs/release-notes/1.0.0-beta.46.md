**An installed Plugin could only be found by name.** Beta 5.5 shipped Plugins, and a Plugin you installed was offered to your agent only when you happened to use a word from its id. This fixes that, and it was found by running the Plugin system on a real installation rather than by a test.

## What was wrong

When your agent is working out what it may reach for, AI17Z narrows the list to the few things that bear on the question. That narrowing knows the names of the groups that ship with AI17Z, so asking about the time finds the clock.

An installed Plugin belongs to none of those groups, so it scored nothing at that stage no matter how well its own words matched. Measured on a real installation: a Plugin whose title and description both said "temperature" was never offered for "what is the temperature there", and was offered for "the next berth slot" only because the word "berth" happened to be part of its id.

The effect is a Plugin that looks installed, looks enabled, looks ready, and is never reached unless you say its id out loud.

## What changed

A group AI17Z has no built-in knowledge of now takes its cue from what the Plugin itself declares: the titles of the capabilities it contributes. A capability's title also counts towards its own relevance, which nothing read before.

Both read only what a Plugin already had to write down in its manifest. Neither involves asking a model, because which tools your agent may later be offered is exactly the judgement you should be able to inspect and predict.

A question that matches nothing is still offered nothing. This makes a Plugin reachable by the words somebody would actually use about it; it does not put one on every menu.

## What has not changed

The twenty groups that ship with AI17Z score exactly as they did, because the new behaviour applies only where there was no built-in knowledge to begin with. Nothing about permissions, readiness, quotas, the host allowlist or the audit trail is different. Everything Beta 5.5 said about Plugins still holds.
