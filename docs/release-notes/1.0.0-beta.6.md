AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

## Your agent was watching one surface out of five

A connected X account had a single thing looking at it: the channel poller, which loads the notifications page. That is the browser activity most people see.

The other four monitors — searching for your handle, searching for replies to it, walking the threads under your own posts, and watching a tracked account — existed, worked, and had nothing telling them to run. They were opt-in, behind a button, on the theory that each one costs a page load. What that produced was an agent reporting itself ready while most of its senses were switched off.

This is exactly the case the mention search was built for: a quiet notifications surface is only *not* silence if the search is actually running.

**A new X account now gets all four**, and an account connected before this repairs itself the next time you press Start. It only ever creates: a monitor you deliberately switched off stays off.

## And turning a monitor off never worked

Chasing the above turned up something worse.

`UNIQUE (account_id, kind, target)` reads as "one source per kind per account", and for the monitors that carry a target it is. For the four that do not, it said nothing at all — SQL nulls are distinct from one another, so two rows with the same account, the same kind and no target never collided.

Which means the code that saves a monitor was never updating anything. It was inserting. Three consequences, worst first:

- **Turning a monitor off did not turn it off.** Easy Mode disables one by saving it as disabled; that wrote a *second*, disabled row and left the original polling. The setting looked applied and did nothing.
- Saving Easy Mode, or pressing "turn on the defaults", added another set of rows each time.
- Duplicated rows meant duplicated page loads on every cycle. Duplicate events were still collapsed into one job, which is why this cost time rather than correctness — and why it went unseen.

Migration 0058 collapses any duplicates you already have, keeping the most recent of each, and rebuilds the constraint so that nulls are no longer distinct. Nothing in the application changed: it was written all along as though this already held.

## Everything from Beta 1.0.0 (5)

**An imported agent can be started.** Importing produced an agent that looked complete and then refused to start, with a message telling you to reopen the agent page — which never created anything. Import now creates the stock pipeline, and an agent already in that state repairs itself on Start.

**Typing works.** One character into any field inside a dialog moved the caret out of it. Fixed and measured: eight keystrokes out of eight lost the caret before, none out of thirteen after.

**The model is a list**, with a button to fetch what the provider offers, and free text still available for a model too new to be listed.

**Paste your key and AI17Z works out whose it is** — Claude, OpenRouter, xAI, Gemini. Always a suggestion, always overridable.

**Google Gemini is supported.** It was missing while every other provider was present.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched. The first start after an upgrade rebuilds and says so.

## Verifying the download

```powershell
Get-FileHash .\AI17Z-Setup-1.0.0-beta.6.exe -Algorithm SHA256
```

Compare against `SHA256SUMS.txt`. The installer is not code-signed yet, so Windows SmartScreen will warn about an unknown publisher.

## Known limits

- **Windows is the verified platform.** The Linux scripts are written and syntax-checked, but nobody has taken a clean Ubuntu machine through the flow.
- **Headless servers are not a supported flow.** Connecting an X account opens a real Chrome window for a person to sign in to.
- **One X account has been run end to end.** Two agents in one installation and two installations on one machine are both tested; two signed-in X accounts side by side are not.

## Requirements

Windows 11, Docker Desktop, Node.js 20+, and Google Chrome. The installer detects what is missing and tells you; it does not bundle them.
