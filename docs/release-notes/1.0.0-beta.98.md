Beta 0.98 lets an owner publish a long development update as a short X thread, and removes two database deadlocks between agent locks and foreign key checks.

## What changed since Beta 0.97

**Development updates can be threads.** An update sent as `parts` (one to six pieces, each at most 280 Unicode code points) is reviewed and published as a thread instead of one post. A one-part update is the same single post as before.

- The Review screen lists every part in order with its position and character count. The owner makes one decision for the whole thread, and can edit each part before it goes out, as long as the number of parts stays the same. Attachments go with the first part.
- The command line accepts `approve <updateId> --parts-file <json-file>`, and `npm run dev-updates -- split --text "..."` prepares a paragraph and sentence split.
- The account needs both post and reply permission. Part one is an ordinary post and each later part replies to the previous part once its status id is confirmed. Every part goes through the ordinary executor, so safety and policy checks cover the whole thread before anything is sent and run again at each send.
- Account cadence and agent rate limits are checked for every part together, once. That admission is recorded on the update, so a recovery cannot admit the same thread a second time. The project ceiling counts a thread as one update, and the account's action limits still count every published part.
- If a part fails, publishing stops and every part that did go out is recorded with its link. A recovery skips parts already done and asks the platform before retrying one whose outcome is unknown. An unknown outcome stops and never sends again. Rehearsal checks every part without creating a public reply target.

**Agent locks no longer deadlock foreign key checks.** The Studio risk watches, the coin alerts sync and a trade mandate activation could each wait on a lock another path held while inserting a row that points at the same agent, and Postgres ended one of them with "deadlock detected". Those paths now take weaker row locks that still keep two workers on the same agent apart, and take their locks in one fixed order: agent, then Studio binding, then radar source. Playbook imports use the same weaker lock. A new regression test drives the real paths and failed before the fix.

This adds migrations 0143 and 0144.

## Known limits

Threads need an account that has granted reply permission as well as post permission. A development update with a single part behaves as it did in Beta 0.97. The thread publisher has been exercised against mocks and test databases, and no run used a live X account.

## Upgrading

Use the updater belonging to the installation you want to update. Beta 0.98 uses the semver tag `v1.0.0-beta.98`. GitHub Actions builds the Windows, Ubuntu and macOS packages and verifies the published release files.
