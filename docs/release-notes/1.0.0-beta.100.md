Beta 1.00 lets an agent work toward a goal in a bounded plan, and lets an owner attach an external MCP server as a read-only Plugin.

## What changed since Beta 0.99

**A goal can drive one bounded plan.** On a wake, an active goal that has not been tried before may get a single attempt. It needs the owner's capability loop opt-in, an autonomy level of THINK or higher, and a configured classifier model. The plan is adaptive: each result feeds the next choice, with a ceiling of three model turns and sixty seconds.

- Below ACT, the first chosen step becomes a proposal for the owner and the plan ends normally.
- At ACT, every step still passes the capability's schema, readiness, permission and execution checks. Permissions, autonomy, goal status, policy and PAUSE ALL are read again between steps.
- An approval request or a refusal ends the attempt, and enabling a grant later never revives it. Writes keep their disabled defaults, and a goal cannot be used to skip the job a channel write requires.
- The goal records the attempt and a one sentence outcome. Each step appears in the trace. No model output or conversation transcript is kept.
- A plan interrupted by a stop is recorded as interrupted and is never replayed, so an action whose outcome is unknown is never repeated.

**External MCP servers can be attached as Plugins.** An owner can attach one HTTPS MCP endpoint (Streamable HTTP) to an agent. Its tools appear as ordinary capabilities under the same permission, readiness, hourly budget and audit rules as every other Plugin.

- Only tools the server marks read-only can run. Everything else is listed as unavailable, and every new tool starts disabled for every agent.
- Tool descriptions are treated as untrusted text. Results are size limited and fenced, and an error that echoes the credential is refused.
- A credential is sealed under the master key for one agent and is never part of the saved manifest or the audit. Changing the endpoint host deletes the stored credentials.
- Refreshing the tool list asks the owner again when a server wants more than before. A tool whose read-only claim or input schema changed has its permissions switched back off.
- There is no local program launch, no sign-in flow and no automatic retry of an interrupted call. Public HTTPS endpoints only.

This release adds one migration, which adds a plan column to goals. Existing goals and agents are unchanged.

## Known limits

Goal plans do nothing for an agent whose owner has not turned the capability loop on. A server's read-only label is its own claim, so the owner still chooses which endpoints to trust. Protocol behavior is tested against a local fake server, not against third-party deployments.

## Upgrading

Use the updater belonging to the installation you want to update. Beta 1.00 uses the semver tag `v1.0.0-beta.100`. GitHub Actions builds the Windows, Ubuntu and macOS packages and verifies the published release files.
