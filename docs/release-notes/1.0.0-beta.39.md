**Beta 4.8 separated two metrics X keeps apart, and broke its own release check doing it.** The package it published was correct and both Macs proved it. Ubuntu and Windows failed on two mistakes in the checking, not in the thing being checked, and this corrects them.

## The retry and the excuse were transposed

Qualification runs the published installer the way somebody installing for the first time does, without a token, against an hourly allowance a hosted runner shares with whoever else is on it. Beta 4.8 added two things: try once more if the attempt failed, and report a refusal that is recognisably that shared allowance rather than counting it against the release.

Those went into the wrong places. The allowance test landed on the retry, so a refused runner printed its note, skipped the retry it was supposed to take, and then fell into the failure below it. The job excused the refusal and failed on it in the same breath.

The retry turns on the attempt having failed and nothing else. Whether the second failure was the shared allowance is asked afterwards, inside the branch that already knows both attempts are gone, and it decides only how that is reported. Exactly one of the two outcomes can happen now, because it is written as a choice between them rather than as two separate questions about the same value.

## Installing a package is the installer's job

The same release added a check that installs the exact published package with no lookup of any kind, which is the half that makes qualification independent of anyone else's traffic. On Ubuntu it did that by handing the file to the package manager directly.

That skipped everything the installer does around it, including being told not to start anything. So the package's own checks ran against a machine whose container engine had never been started and reported it, and a qualification job failed over a service it had not been asked about.

The installer takes a local package and a hash for exactly this, and it is what runs now, which is also what the macOS half was already doing. That difference is why one passed and the other did not.

## What Beta 4.8 got right

Worth saying, because it is the part that was being tested. Both Macs qualified, including the one that had failed on the two releases before it, and the published bytes check passed. The package was never in question: what failed was the new checking around it, on two platforms, in ways that had nothing to do with each other.

The deterministic half now runs the same way everywhere. Fetch the asset from the address that contains the tag, check it against the checksums that tag published, install it through the installer with that hash, and ask nothing of any API. What a stranger's unauthenticated route does is still exercised, still bounded to two attempts, and still reported rather than trusted.

Both mistakes are held by tests that fail without the fix: one that the allowance is never consulted in the retry, and one that the package is installed through the installer rather than around it.
