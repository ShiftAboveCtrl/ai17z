**A tool that ships with AI17Z could not start.** The Response Lab's batch evaluator is part of every installation, and on an installed copy it failed before running a single line. This fixes it. Nothing else changes.

## What was wrong

AI17Z's images are built from the directory the application was installed into, so the `tools` folder ships with it. One of those tools, the batch evaluator that runs the Response Lab corpus and lays the answers out together, imported a helper that only exists in the source repository's test folder, which is not shipped.

That import ran at the top of the file, so the tool failed with a module-not-found error before doing anything, including for the ordinary run that does not need that helper at all. An installation has its own worker, which is exactly what that run relies on, so it was the one run an installed copy could have done.

## What changed

The helper is now loaded only on the code path that actually uses it. The tool starts and runs on an installed copy, and behaves exactly as before in the source repository.

A shipped file that cannot start is worse than one that is absent, which is why this is a release rather than a note.

## What has not changed

Nothing about Plugins, agents, capabilities, permissions, the pipeline, the interface or the database. Everything Beta 5.6 said still holds, and the Response Lab reaches the same conclusions by the same route.
