**A metric that was being renamed, a count that five screens disagreed about, and a release check that could be decided by somebody else's traffic.** All three were found by measuring rather than by reading: a live signed-in browser, the two installations' own databases, and the logs of the last three releases.

## Views are not impressions

X writes two different numbers in two different places, and AI17Z was calling both of them impressions.

The count group under a post says "288 replies, 155 reposts, 696 likes, 60 bookmarks, 58814 views", and the figure beside the post is labelled Views. X's own analytics view, which an account only has with the entitlement for it, says Impressions. Nothing establishes those are the same measurement. A label table mapped the word "views" onto the impressions metric, so the figure was stored, reported and shown under a name X had not used.

They are separate now, everywhere: the reader, the capability's result, the column it is stored in, the growth series and the screen. A reading carries whichever X actually gave, and the other stays absent rather than becoming a nought, because a figure nobody measured is not a figure of zero.

The readings already recorded were not left mislabelled and were not guessed at either. Every one of them came from the radar, which reads the count group and has never had access to an analytics view, so its provenance establishes what the number is: 83 readings on one installation and 2,513 on the other move to the name they were always measured under. Readings from the analytics reader are genuinely ambiguous, because it could see either word on the page, and those are left exactly where they are.

## Asking a post whose it is

The same capability decided whether a post was the account's own by looking for the analytics link X puts on it, on the reasoning that X shows that link to the author.

It does not. Measured against the live session on somebody else's post: the link is there too, reading "58.8K Views". It is on every post and proves nothing about who wrote one.

Whose post it is now comes from the same signal the rest of the reading layer uses, the focal article's author against the account's own handles, anchored on the article that links to its own status id. Somebody else's post is refused with both names in the sentence, so what was established is visible rather than implied.

Underneath that, the address had been wrong in a way no amount of retrying would have fixed. The reader navigated straight to an analytics address; X's router only resolves that from inside the application, and a direct navigation renders the home timeline instead. Waited out for fifteen seconds, twice, it still rendered the home timeline. The post is loaded first now and X's own link is followed from there.

## Five answers to "what is waiting for you"

The screen an owner opens first said two things were waiting. The inbox beneath it offered one. The agent card said two. The activity header said two while its own filter chip, reading the inbox, said none.

None of them was lying. There were five separate pieces of code answering one question: three added two job statuses together, one had a statement of its own, and only the inbox knew that a Response Lab rehearsal is held in a decision state and publishes nothing, so there is no decision to make about it.

There is one definition now, and the rehearsal test inside it is shared with the inbox so the two cannot drift. Health, the Telegram status reply, the activity header, the jobs API and the agent card all ask it.

## A release check decided by somebody else's traffic

Two of the last three releases failed a post-publish qualification job, and both times the release was correct: the other runner installed the same package from the same addresses while its neighbour was refused.

The cause is that the published installer resolves a release through an API without a token, because that is what somebody installing for the first time does, and a hosted runner shares its address with whoever else is on it. Sixty requests an hour between all of them. Whether a package is correct was being decided by how much of that budget was left.

The two questions are separated now. Whether the published package is correct is answered from the tag's own addresses: fetch the asset, check it against the checksums that tag published, install from those bytes. No lookup, nothing shared, nothing to run out of. Whether somebody installing unauthenticated can still resolve a release is answered too, bounded to two attempts, and reported rather than trusted: a refusal that is recognisably the shared ceiling is said out loud and counted as neither pass nor fail, and a failure for any other reason still fails the job.

What that decision means is one function now rather than a text match written out per platform, and it is exercised on every test run against a rate limit, a timeout, a corrupt archive, a checksum mismatch, and the empty output that defeated the previous version of this.

## Smaller things, all found by looking

**A failed install reported fourteen failures.** Everything after the install asks the installed copy about itself, so a runner that never installed anything had nothing to ask and said so fourteen times. One of those was the cause. It stops at the cause now.

**An empty inbox and an unreadable one were the same answer.** Every other reader in the X layer establishes which it is before accepting nothing; the message inbox and the conversation reader did not. A refused page would have arrived as "nobody has messaged you".

**A pool with no trades and a payload nobody could read were also the same answer.** A missing candle list became an empty history and a successful result. The list being absent is a change in the source and is refused as one; a genuinely empty list is still a measurement.

**The activity list called everything a reply.** An original post arrives on a scheduled trigger and was shown as a reply to @unknown, which is two wrong statements about one row. It reads the action type now, and a post the agent thought of itself says so rather than naming a stranger.
