`v1.0.0-beta.68` is two corrections to the paper trading engine and the shared
utility runtime, both found by the first live canary of a utility runtime
deployed beside AI17Z Studio, and one addition to that runtime: the public,
read-only capabilities an agent already has, offered to Studio's callers
through the same invocation path.

## A paper fill reports what arrives, in the units it arrives in

A paper fill reported what would have arrived as what was spent, less the fee,
**in the units that were spent**. There was no price in it at all. A tenth of
an ether spent on USDC was reported as having received
99,950,000,000,000,000 base units of a coin with six decimals, which is
ninety-nine billion dollars.

Every fixture priced its asset at exactly one unit of the other side, with
eighteen decimals on both, which is the one market in which spending and
receiving are the same number. The live canary priced USDC in WETH from a
median of four Uniswap V3 pools and the fill was wrong by the price.

What arrives is now converted at the price the fill executed against, using
the priced asset's own decimals. The floor a trade asks for (`minOut`) had the
same assumption in a milder form: it was right for a purchase of the priced
asset and wrong for a sale of it, by the price squared. Both now go through one
conversion, `amountOut`, and know which side of the price the input is on.

Nothing here touched value. A paper trade forces paper mode in core, and no
argument makes it live. What was wrong was the record of what a simulation
said would have happened.

## A runtime with no owner says so

The shared utility runtime keeps each caller's paper journal as an agent, and
an agent belongs to an owner. A freshly deployed runtime has none, and it
answered a paper trade with `500 INTERNAL`. A gateway reads that as a refusal
and fails the caller's job, where the right answer is to wait for an operator
to finish setting the runtime up.

It now answers `503 UNSAFE_CONFIGURATION` with a sentence naming the endpoint
that creates one, the same class it already used for a missing signing secret.
The capability listing reports `configured` only when there is both a secret
and an owner, and says `needsOwner`, so a gateway can tell somebody before they
wait on a trade that cannot run.

## Public capabilities on the shared runtime

The utility runtime answered three things: a paper trade, a paper portfolio and
a market snapshot. Core has carried far more for its own agents for some time:
exact asset resolution, market history, chain and contract reads, transaction
and event decoding, token risk evidence, DeFi and governance data, reference
and research lookups. `capability.invoke` offers them to Studio's callers.

It is an **allowlist of exact ids**, `UTILITY_BRIDGE`, rather than every
capability that reads. A capability added to core for an agent's own use does
not become something strangers can call the day it merges. Each entry is also
judged at call time against its own declaration, so one that later becomes a
write or owner-only is refused rather than trusted. Absent on purpose: the
agent's own workings, its wallet, anything needing an X session, an owner's
watched repositories, and the archive capture, which declares a read but asks
somebody else's service to do something.

Every call goes through `invokeCapability`, the path an agent's own call
takes: the capability's input and output schemas, its timeout, its readiness,
and the upstream budgets every caller of the runtime shares. It is recorded
like any agent's invocation. The capability listing now publishes what the
bridge will run, with each input shape in the words an agent's own menu uses.

## Upgrading

Nothing to do. No migration, no setting, no change to how an installation runs.
