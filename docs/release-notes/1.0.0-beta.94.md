Beta 0.94 gives owners more control over what their installation shows Studio, and adds two owner controls that were missing.

## What changed since Beta 0.93

**League entry and capture hosts have owner controls.** The Studio panel on the Plugins screen can now enter a league season, and each outcome is a sentence: entered, already entered, season closed or not linked. Replacing an existing paper mandate needs an explicit checkbox. The advanced policy screen now has an editor for the hosts a screenshot capture may visit; only bare public hostnames are accepted.

**A token check answers with a sourced evidence card.** A direct check needs a real token signal such as an address or ticker. The card says what was read, where from and how fresh. An owner-approved card whose readings expired is read again before sending: identical readings send the approved text unchanged, and anything different goes back to review. This adds migration 0132.

**The public activity tape can carry the real post.** A published post or reply can carry its stored status link, and its words only if the owner turned that on, only for posts made after they did. Consent is checked again immediately before sending. A dry run, an unverified post, another service and a receipt carry no link.

**Radar pins are opt-in per watch.** An exact ticker watch can share its ticker and stored source post with the activity tape. Existing watches stay private. Withdrawing consent, disabling or deleting the watch, or turning the tape off queues removal of what was shared, and an installation that never turned the tape on sends no withdrawals.

**Public home snapshots can include stored X observations**, only when the owner opted in. A measured follower count is kept over a newer reading that did not measure followers.

**Agent SHARE exports carry a redacted public profile.** It contains configuration only, never memories, relationships or credentials.

**The installed package keeps the faker override link.** Beta 0.93's package was missing the link that points `@farcaster/core` at the bundled faker compatibility package, because the package archive drops links. The native worker then crashed on start with `faker.datatype.number is not a function`, so no installed copy could drive Chrome. The packager now replaces such links with real copies, refuses any link it cannot carry, and proves `@farcaster/core` loads from the staged application. The install check now also confirms the native worker is running. Installations on Beta 0.93 are repaired by updating.

## Known limits

Studio must be updated first to show the new link, words and radar details; an older Studio receiver still accepts the batch with radar details removed. The evidence card and activity tape changes have been exercised against mocks and a test database, not against live X.

## Upgrading

Use the updater belonging to the installation you want to update. Beta 0.94 uses the semver tag `v1.0.0-beta.94`. GitHub Actions builds the Windows, Ubuntu and macOS packages and verifies the published release files.
