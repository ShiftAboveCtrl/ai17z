**Beta 5.2 published correctly and then failed its own check.** The packages were right, all five platforms qualified, and the step that reads the published bytes back rejected the release over a file that is not installed from. This corrects that, and holds the two lists against each other so it cannot happen again.

## What went wrong

Beta 5.2 started publishing the release notes as a file, so an update check can read them as the Markdown they were written in rather than asking an API for rendered HTML.

Every published asset is then checked for a line in `SHA256SUMS.txt`, and the notes had none. That check is right to exist and was right to fire: a package published without a hash is one no installer will accept, because neither the command nor the setup program will unpack a payload whose hash it cannot establish.

But the notes are not a payload. They are read over the network by the update screen, they are deliberately allowed to be missing so a release made before they existed still updates, and nothing installs from them. So they belong with the manifest and the two reports, which are exempt for the same reason, rather than in a list whose whole meaning is "this is safe to unpack".

The fix is one name in that exemption. Nothing about what is verified before installing changes.

## The part worth more than the fix

Adding an asset has two valid answers and one wrong one: hash it, or record why it is not installable. Doing neither produces a release that is published, tagged, and then rejected, which is the most expensive moment to find out.

Those two lists now have to agree. A test reads the assets the release workflow publishes, the names the checksum step hashes, and the names the published-bytes check exempts, and fails if anything is in the first list and neither of the others. Run against the previous release it names the exact file and says it was published with neither a hash nor an exemption.

That is the whole correction: the mistake was cheap, finding it was not, and a failing test is the cheapest place to find it.

## Beta 5.2 itself

Worth stating plainly, because the red mark says otherwise. Its packages were correct and installable. Every build succeeded, the release published fifteen assets, its manifest agreed with its tag and its commit, and all five platform qualification jobs passed against the published bytes. What failed was the bookkeeping, about a file no installer reads.
