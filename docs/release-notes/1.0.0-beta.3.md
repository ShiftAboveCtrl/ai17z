AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

This release is about the checks. Beta 1.0.0 could not be opened at all, and four separate things that were supposed to catch that had reported success without looking. Everything in Beta 1.0.0 (2) is here too.

## What was actually broken

**The interface went black.** A React hook sat below an early return in the agent list. React counts hooks by call order, so the first render called seven and the second called eight; it answers that by throwing during render and unmounting the whole page, leaving an empty document over the application's own near-black background.

**And upgrading would not have delivered the fix.** `docker compose up -d` builds an image only when one is *missing* — it has no idea the source changed, and AI17Z only rebuilt when explicitly asked. The Docker project name comes from your data directory, which an upgrade deliberately does not touch, so the previous version's images were still there and still started. You would have downloaded the fix, installed it, and seen the same fault.

Both were fixed in Beta 1.0.0 (2). This release is what makes them hard to repeat.

## The checks that were not checking

- **The installer gate fetched the interface and checked for HTTP 200.** That is nginx handing over an `index.html` with an empty div in it, equally true of an interface that crashes the moment it runs. It now creates the owner account, signs in through a real browser, and waits for the agent list to draw — after a fresh install and again after an upgrade, and it fails if the images did not move to the version that was installed.
- **The release tooling was not typechecked.** The gate, the packager and the secret scan were outside the TypeScript project. A syntax error in the gate passed `npm run typecheck`.
- **There was no linting at all**, so `react-hooks/rules-of-hooks` — the rule written for precisely this bug — had never run. It now runs in CI and in the release gate. It found 51 things, including a duplicate copy of the function that reads a post off a timeline, and a stale closure in the review queue's keyboard shortcuts that could have approved a reply using out-of-date state.
- **The releases page was named by the workflow, not by AI17Z.** It called this `AI17Z 1.0.0-beta.3` while the installer wrote *AI17Z Beta 1.0.0 (3)* into Add/Remove Programs. One name now, derived once.

**There is also an error boundary**, which there was not before — and that is the real reason a one-line mistake became an unreadable screen rather than a message. Any render error now names what broke and where, and offers a way back.

## Everything from Beta 1.0.0

**Move an agent to a new machine without re-typing your keys.** A MOVE package can carry the provider API keys the agent's models use — only those, never every credential in the installation. Off unless you ask for it, refused outright on a SHARE package, declared before you import, and named `-with-keys-SECRET` so you notice it in a folder listing. The file holds them in the clear because a key sealed under the master key of the machine it is leaving is useless on the machine it is arriving at; import re-seals them under the receiving installation's own key.

**The installer looks for AI17Z before offering to install one.** It reads the registry and the usual directories, lists what it found, and asks whether to update that installation or set up a second alongside it. On an update it skips the questions it already has answers to.

**Ports pick themselves.** It walks up from the default until it finds a free one, so the common case is pressing Next.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely — off means no request is made at all.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched. The first start after an upgrade rebuilds and says so; that takes a few minutes and only happens when the code has actually changed.

## Verifying the download

```powershell
Get-FileHash .\AI17Z-Setup-1.0.0-beta.3.exe -Algorithm SHA256
```

Compare against `SHA256SUMS.txt`. The installer is not code-signed yet, so Windows SmartScreen will warn about an unknown publisher.

## Known limits

- **Windows is the verified platform.** The Linux scripts are written and syntax-checked, but nobody has taken a clean Ubuntu machine through the flow.
- **Headless servers are not a supported flow.** Connecting an X account opens a real Chrome window for a person to sign in to.
- **One X account has been run end to end.** Two agents in one installation and two installations on one machine are both tested; two signed-in X accounts side by side are not.

## Requirements

Windows 11, Docker Desktop, Node.js 20+, and Google Chrome. The installer detects what is missing and tells you; it does not bundle them.
