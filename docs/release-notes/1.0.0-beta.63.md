**The reason an updated installation could keep the previous release's dependencies, found and removed.**

- **Beta 7.2 made this visible; this stops it happening.** Beta 7.2 added a check that reads the dependency lockfile back out of the running images and compares it with the one the installation ships, after two real installations turned out to be serving a dependency the release before had already replaced. On the very next update that check fired again and named the cause: Docker was handing its builder a stale copy of the program folder.
- **Why Docker could not tell the folder had changed.** The package fixes the timestamp on every file inside it, on purpose, so that the same input always produces the same archive and the hash the install command checks is the identity of what you downloaded. Extracting it put that fixed timestamp on disk as well. Docker's builder decides whether a file in its build has changed from its name, its size and its modification time, and a version bump changes a manifest without changing its length: the lockfiles of the last two releases are both exactly 261594 bytes. So nothing it looks at moved, and it kept using the copy it already had.
- **The fix is one line in the right place.** Files are now stamped with the moment they were written, rather than the moment the archive claims. The archive stays reproducible, and the folder stops reporting that nothing happened. The installer's own verification asserts it after every install.
- **The Beta 7.2 check stays.** It is what caught this, and it remains the thing that would catch anything else of the same shape.
- Everything in Beta 7.2 is included.
