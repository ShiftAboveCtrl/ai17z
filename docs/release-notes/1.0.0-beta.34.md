**An agent that was handed the right tool and still said it could not help.** Beta 4.3 fixed which tools an agent is shown. It was right about the list, and the agent refused it anyway, for two reasons that both sit above the list.

## The question reaches the tool list

Beta 4.3 stopped the shortlist being judged against the agent's own persona. That was necessary and it was not all of it, because the layer it was left with is not a question either. On a real reply that layer carries what the agent remembers, what was looked up a moment ago, the evidence verdict, who is speaking, the task framing and the output rules, wrapped around one line of incoming text. Most of it says reply, message and channel and names a handle, which is why reads of X kept winning the list.

What was actually asked is now passed in by the part of the pipeline that knows which line it is. Asked the time, an agent is offered the clock and nothing else.

## Being told a lookup failed is not a reason to stop looking

That turned out not to be enough on its own.

An agent looks things up before it writes, and it can reach for a capability while writing. So a web search that failed a moment earlier is not the end of the search. The prompt did not say so. Around the evidence verdict sat two flat instructions, "say you do not know rather than guessing at those" and "say plainly that you do not know", and two instructions to refuse beat one conditional permission to look. An agent offered the clock, and nothing else, read them in order and answered that it could not check the time.

Both sentences now defer to the capabilities when there are any, and are unchanged when there are none, which is the case where a failed lookup really is the end of the search.

Nothing here relaxes what the agent has to admit. A capability that was offered and never called, or called and failed, is not evidence of anything, the reply still has to say it does not know, and the prompt still refuses to let it fill the gap with something that sounds right.

## A question is not sent to a search engine when something here answers it

Underneath both of those was a plainer mistake. "what time is it where you are right now" contains "right now", which is on the list of phrases meaning an answer changes by the day, because nearly everything else carrying those words does. So the question went to a search engine, which cannot answer it, and that failure is what produced the refusal above.

A lookup that an available capability already answers is now left to it. This is a rule about which source goes first rather than about any one question, so it is applied in one place, to the deterministic rules and to a plan a model proposes alike, and nothing in it knows what a clock is.

Two conditions, both of them things a capability already declares. Whether it can answer the question is the same judgement used to choose the menu, made without a model call. Whether it can answer it **now** is its readiness, which is what keeps this safe: a capability that needs a connected account or a browser and does not have one cannot displace a search, or a question would lose every source it had.

Only one capability, and only when it is the only one that matches. Offering a menu can afford to be generous and removing a source cannot, so a question several capabilities merely brush against keeps its search. "what did the protocol announce at the summit today?" matches a total-value-locked reader on the word protocol, and that is not an answer.

## What this was checked against

Three questions, through the whole pipeline, against a real agent with a real model:

- asked the time, it reads the clock and answers with it, to the minute
- asked whether its browser is working, it reads its own diagnostics and is right about a browser that had been down a day
- asked what the project shipped, its web lookup still failed, and it read the repository it watches and named the releases

The third is the one worth keeping. Two capabilities matched that question, so nothing was suppressed and the search ran and failed exactly as before. The agent reached past the failure to the thing that could answer, which is the other half of this working on its own.
