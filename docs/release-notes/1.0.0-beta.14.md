AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

## Your agent can look things up for itself

Until now an agent answered from its persona, its memory, the conversation, whatever the runtime had already looked up for it, and — since Beta 1.0.0 (12) — twelve things it could read on X. This release adds fifty-six more, and one screen where you decide which of the sixty-eight it may touch.

**Crypto & Onchain** — forty-five of them. What a contract is and whether its source is verified, including the awkward case where the address is a proxy and "verified" has two answers. Balances, transactions, receipts, logs and blocks across seven EVM chains, plus Solana and Bitcoin on their own terms rather than pretending they are Ethereum. What a token is worth and where the depth actually is. Where value is locked, and what a stablecoin's supply looks like chain by chain. What a DAO has voted on, at the block the voting power was measured at. What security services have observed about a token or an address — observations, never a verdict.

**Reference & Knowledge** — six. What an established term or person is, from reference works. Scholarly works by DOI or arXiv id, including whether one has been retracted or corrected. Structured facts about an entity, with the ambiguity kept: Mercury is a planet, an element, a god and a record label, and an agent that picks one silently is guessing.

**Web & Feeds** — three. What a page said on a date in the past, from the public web archive, always reported with the date it was captured. What a site has published to its RSS or Atom feed.

**Company Filings** — two. What a public company has filed with the SEC. This one needs a contact email before it will work, because EDGAR refuses callers who do not declare one. Set `AI17Z_SEC_CONTACT` in your environment file to the address the SEC should use to reach you, and restart. There is no default, because a contact address baked into a release would name the wrong person to a regulator on every machine that runs it. Leave it empty and the group reports itself unavailable and sends nothing at all.

**X** — the twelve from the last release, unchanged.

## Deciding is one switch, not sixty-eight

The screen asks about groups. "Let my agent look things up on chains" is a thing somebody wants; `chain.read_receipt` is not a decision anybody wants to make sixty-eight times. That screen is new too: before this release the twelve X capabilities were a flat list of switches, and sixty-eight of those is not a screen anybody reads. Each group has one switch, an honest count of how many of its members can actually work on your installation right now, and an Advanced list behind it if you do want to set one individually.

Turning a group on means each capability's own default — reading allowed, anything that writes still off or still asking. It is not a sweep to Allowed, because "let it look at chains" is not consent to let it act.

A group you have overridden individually says so, and warns you before the group switch replaces those choices.

**Nothing here is on unless you turn it on.** An agent that has never been near this screen behaves exactly as it did before, and the release includes a test that fails if it does not: an agent with every group off still generates, still remembers, still acts, and makes no outside request from anything switched off — proved by watching the machine's own network sockets rather than by trusting the code to be well behaved.

**Every source says where its answer came from.** A lookup carries the name of the service that answered, and a failed lookup is reported rather than smoothed over, because an agent that quietly invents the answer it could not fetch is worse than one that says it does not know.

## Three things that were wrong

**Every installed copy has been reporting the wrong build.** Since before Beta 11, the version display and the worker heartbeat showed `1.0.0-beta.1` as the exact source of whatever you had installed. It was a twelve-character slice taken off the front of something that was never a commit — a plausible-looking string, which is the only reason it survived three releases. Both ends are fixed, and anything unrecognised now says "source unknown" instead of showing a mangled prefix.

**Exporting an agent left its capabilities behind.** An agent package carried what the agent may do through an account, but had nowhere to put what it may reach for while answering. Importing gave you back an agent with every one of those decisions reset. They now travel with the file, and a capability the receiving installation has never heard of is reported rather than invented.

**A silent upgrade could install over the wrong copy.** If you run two installations and upgraded one with `/VERYSILENT`, it had no wizard to read the instance name from and fell through to the default — wrong folder, wrong uninstall entry, nothing appearing to fail. `/INSTANCE=` now settles the program folder, the Start Menu group, the uninstall identity and the data directory together. Upgrading through the installer window was never affected.

## Everything from Beta 1.0.0 (13)

**A like that had already happened is no longer reported as a failure.**

**Your agent reads its own account on a schedule**, about four times a day, so the follower history on the Analytics screen actually fills in.

**Twelve things your agent can reach for on X while it is answering** — posts, profiles, conversations, search, notifications, follower lists, timelines, your direct message inbox, a post's own figures, and liking and reposting.

**X Studio** — a screen of its own showing what your agent has seen and what came of it.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched. The first start after an upgrade rebuilds and says so.
