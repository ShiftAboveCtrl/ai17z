AI17Z is a local-first platform for running autonomous agents on your own machine. An agent is an identity, a memory, a model, a policy, and a set of channels it can act on.

## Stopping one installation stopped all of them

If you have two copies of AI17Z installed, "Stop AI17Z" on either one stopped the other one's browser worker as well — and with it the real Chrome that worker was holding your signed-in X session in.

The worker was found by the name of the script running it, which is the same name in every installation, so nothing tied the process being stopped to the copy doing the stopping. It now only stops workers running out of its own program folder, which is the same question the diagnostics and the uninstaller already asked.

This is the expensive kind of bug: getting a browser session back means sitting down and answering a security challenge.

## Setting an agent up now leaves you with one that can run

Connecting a provider and choosing a model were two steps that did not talk to each other. Testing your key first and picking a model afterwards discarded the model without saying so, and the review screen at the end read your unsaved answers rather than the agent — so it could describe a model the agent did not have.

The model is saved when you press Continue, the review screen asks the server what is actually stored, and "your key works" and "a model is configured" are two different statements because they are two different things.

**Reconnecting a provider no longer fails.** Adding one you already had returned a database error; it now updates the one you have. Leaving the key box empty on a reconnect keeps the key you already gave it rather than clearing it.

**A model id is shown exactly as the provider writes it.** `deepseek-v4-pro` was being title-cased into something that looked like an id and was not one.

**Advanced setup now tells you what is missing.** It used to create the agent and take you to its page, so a blank model was first reported by a job that failed hours later. It runs the same check Easy Mode does and shows what is unfinished — without refusing; the agent is still created.

**Choosing a model is one control everywhere.** Three screens had three different pickers, and the one on the agent page silently blanked a model your provider had not listed.

## Review before action now means the action happens

Advanced setup started agents in review mode *and* turned dry run on. So the mode whose own description says it waits for you to approve before anything is sent held a reply, took your approval, and sent nothing.

Two safety nets, the second quietly defeating the first, and only on one of the two ways in. Easy Mode has always had dry run off. Advanced now matches, and the toggle — still there for anybody who wants both — says what switching it on does to a held reply.

**Asking an agent to act now does the action it is configured for.** The manual trigger always asked for a reply, whatever the account was linked to do.

## Around thirty settings the runtime enforces were reachable from no screen

The worst kind of defect: the system works exactly as designed, says so, and leaves you with no move. Every policy your agent obeys is now either on a screen or explicitly marked as internal with the reason written down — and a new one cannot be added without that decision being made.

The policies screen is eight labelled groups — Automation, Identity, What it writes, Who it answers, What it reads, Positions it holds, Voice, and Tools and addresses — instead of one flat wall. Blocked topics, forbidden hashtags and links, minimum length, your disclosure statement, link handling, video analysis and signature phrases are among the things you can now actually set.

Saving in Easy Mode still leaves every Advanced-only setting alone.

## The agent page

**Infrastructure problems say whose problem they are.** A missing browser worker was described four different ways in four places, only one of which said how to fix it — and the notification told you to run a developer command an installed copy cannot run. There is one explanation now, and it says this is AI17Z itself rather than anything about your agent.

**Keyboard and screen-reader support.** Eleven pickers were rows of plain buttons; they are proper radio groups now, with arrow keys that move and select. Dialogs trap and restore focus. Hints and errors are read out with the field they belong to. The agent's name is announced once rather than twice.

**A tool that could never run has been removed.** `http.fetch` had a switch, an allowlist and an editor, and nothing in AI17Z could ever call it.

**The interface stops asking questions while you are not looking at it.** Six background pollers ran forever in a hidden tab — on the machine your agent is driving Chrome on. They stop when the tab is hidden and answer immediately when it comes back. Switching between areas of the agent page no longer refetches everything it just fetched.

**Long operations say how long they have been going.** Building a character can take a minute and a half and used to be a spinner inside a button.

## X

**A reply could arrive with its first characters missing.** On a status page X shows an inline composer and then opens its reply dialog on top, about half a second later. AI17Z looked once, bound to the composer that was about to be superseded, typed eight characters into it, and typed the rest of the draft into the real one. It then spent a twenty-second timeout on every reply waiting for an element that never goes away.

It now waits for the composer X actually settled on, and checks the whole draft against what landed rather than the first sixty characters.

**Addresses and the posting schedule can be reached.** The validator refuses any contract address the agent was not given — correctly, because a model asked for one it does not have invents it — but the field that grants them was not on any screen. Posting had the same shape: the schedule was shown on one screen and the only switch that turned it on was on another.

## Underneath

Every column whose values are fixed is now checked against the database itself, so a value added in code without a matching migration fails a test rather than failing on your installation. Provider details — labels, endpoints, which ones appear in Easy Mode, how a pasted key is recognised — are declared once instead of in eight files that had already drifted.

The two largest files in the X and pipeline code, about 1,650 lines each, are now nine smaller ones organised by subject. Nothing moved between functions; only which file they sit in. That split has since been exercised against real Google Chrome.

## Updating

Nothing updates itself. AI17Z asks GitHub what has been released at most once every six hours, shows you the notes, and offers a link. You can ignore it, skip a version permanently, or turn the check off entirely.

Run this installer over the top of an earlier one. Your agents, memories, provider keys and settings live in your data folder and are not touched. The first start after an upgrade rebuilds and says so.
