# Radar evidence extension

## Public home consent extension

Reuse the same ink, bone, Archivo and Kanit system in the Studio panel. The primary action is preview, followed by a separate owner confirmation. Use a single column, 48px controls, visible labels, native validation, selectable wrapping JSON and a live status message. Focus moves to the preview heading. Editing choices clears the preview. State always says last confirmed; stale or failed confirmation never looks live. The removal control explains that copies cannot be recalled. No decorative motion or new visual identity is introduced.

Domain: financial observation in an existing desktop application. Preserve the established Archivo and Kanit typography, ink surfaces, bone text, calm accent, rounded panels and focus treatments.

Primary action: pin an exact address and a measurable predicate. Owner pins are the bounded universe. A ticker cannot configure a watch. Unsupported chains remain visible with an explicit explanation.

Structure: configuration, retained baselines, prospective before/after candidates, posting outcome. The signature is the paired evidence record: source, observation time, definition and gap shown beside each value. Unavailable never reads as zero or safe.

Layout: single-column form, wrapping exact addresses, paired evidence cells in a responsive grid. Every grid child has min-width zero. Controls are at least 48px high; identifiers disable spelling and capitalization. At 390px each value remains readable without horizontal scrolling. Reuse existing design tokens rather than introduce a second visual identity.

Motion: existing button state transitions only. No autonomous motion or decorative financial charts. Baselines and evidence are static and selectable.

Receipts extend the evidence record with Before, At post and Now. At post means the source observation behind the original action, with its actual source time, never an implied live sample. The three cells stack on small screens and share three flexible tracks on wide screens. Pending, skipped, unavailable, queued and published are distinct text states. Each refusal retains its reason. No hit-rate, investment outcome or trading scoreboard is shown.

Trust: no buying or selling instructions, price predictions, safety verdicts, wallet attribution or signer. Sampling never posts directly. Show missing data, provider definitions and the actual job status and refusal reason. Publishing is an explicit option, disabled by default.

States: baseline not read, unsupported chain, unavailable upstream, armed, condition latched, context only, pending idea, queued job, dry run, posted, declined. Errors use visible text and an alert live region. Long mints wrap anywhere.

## Paper league entry extension

This is a small addition to the existing agent Studio Command view. Follow the
current Studio visual language and shared Panel component. The audience is an
owner choosing a simulated season, and the primary action is Enter paper season.

Use the existing ink, bone, border, input and button tokens, typography and rounded
controls. Keep the form single column with visible labels and 48px controls.
Name simulation before the action and require explicit consent before replacing
the owner's paper mandate. Show current entry state and refusal or retry feedback.
Hide the control while the journal is off. Preserve Studio's existing layout and
assets; this addition introduces no imagery or motion.

Check desktop at 1440px and mobile at 390px. Verify keyboard focus, error feedback,
pending submission, alias correction, and the absence of horizontal overflow.
